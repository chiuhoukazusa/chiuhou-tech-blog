Deferred Shading Renderer 延迟渲染管线

项目目标

实现完整的**延迟渲染（Deferred Shading）**管线。延迟渲染是现代游戏引擎的核心渲染技术，其核心思想是将几何信息存储在 G-Buffer 中，然后对每个像素独立计算光照，使得光照复杂度与场景几何体数量解耦。

延迟渲染原理

为什么需要延迟渲染？

传统前向渲染（Forward Rendering）：

  • 每个几何体 × 每个光源 → 复杂度 O(geometry × lights)
  • 每个像素可能被多次着色（被遮挡的像素也计算光照）

延迟渲染（Deferred Shading）：

  • 第一遍：将所有几何信息存入 G-Buffer
  • 第二遍：对每个屏幕像素读取 G-Buffer，计算光照
  • 复杂度 O(pixels × lights)，且每个像素只着色一次

G-Buffer 设计

本实现的 G-Buffer 包含以下通道：

Buffer 类型 内容
Albedo Buffer Vec3 RGB 漫反射颜色

Normal Buffer Vec3 世界空间法线（归一化）
Depth Buffer double 射线参数 t（线性深度）
Position Buffer Vec3 世界空间坐标

技术总结

学到的技术点

  1. G-Buffer 设计：延迟渲染的核心是设计好 G-Buffer 的数据布局，需要存储重建光照所需的最少信息
  2. 法线编码：将法线从 [-1,1] 编码到 [0,1] 存储，可视化时颜色有意义
  3. 阴影偏移：Shadow Ray 起点需要沿法线方向偏移（0.001），避免自遮挡 Z-fighting
  4. Blinn-Phong vs Phong：Blinn-Phong 使用半角向量，比 Phong 更物理准确且计算更稳定

延迟渲染的优缺点

优点：

  • 光照计算与几何体数量解耦
  • 可支持大量动态光源
  • 每个像素只着色一次（没有 overdraw）

缺点：

  • G-Buffer 占用大量显存带宽
  • 无法直接支持透明物体
  • MSAA 抗锯齿实现复杂

遇到的坑

  1. convert 命令不可用：系统没有 ImageMagick，需要改用 Python3/PIL 做 PPM→PNG 转换
  2. 未使用变量警告：-Wall -Wextra 下，未使用变量会产生 warning，需要用 (void)var_name 消除
  3. assert 需要 #include <cassert>：C++ 不像 C 那样隐式包含
