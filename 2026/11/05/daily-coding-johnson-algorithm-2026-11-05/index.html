Johnson 算法 —— 稀疏图上带负权边的全源最短路

① 背景与动机

在图论算法里，「最短路」是出现频率最高、也是唯一一个几乎每个算法工程师都绕不开的问题类别。它的问题规模可以很小——比如一个城市地铁换乘查询里几十个站点的最短路；也可以很大——比如社交网络里几亿节点之间的平均距离、或者物流网络中任意两个仓库之间的最优运输路径。

我们通常会问两类最短路问题：单源最短路（SSSP）和全源最短路（APSP）。

单源最短路的意思是：给定一个起点 s，求 s 到图中其它所有节点的最短距离。这个问题已经有两个经典且高效的解法：

  • Dijkstra 算法：在非负权图上，用优先队列（二叉堆）实现，时间复杂度是 O((V+E) log V)，也就是 O(E log V)。这是目前已知最快的通用 SSSP 算法（在非负权前提下）。
  • Bellman-Ford 算法：能够处理带负权边的图，但它的代价是 O(V·E) 的复杂度——每条边要被松弛 V-1 轮。这个平方级别的复杂度在稍微大一点的图上就让人难以接受。

那么全源最短路呢？所谓全源，就是要求任意两对节点之间的最短距离，一共 V(V-1) 对，通常表示为一张 V × V 的距离矩阵。

一个最直观、也最「暴力」的做法是：对每个节点都跑一次单源最短路。

  • 如果对每个节点跑一次 Dijkstra，复杂度是 O(V · E log V)，在非负权图上这是一个非常漂亮的结果。
  • 如果图里有负权边，Dijkstra 就失效了（Dijkstra 的正确性建立在「每次弹出的节点距离不可能再被更新」这个假设上，而负权边会破坏这个假设）。这时我们只能退而求其次，对每个节点跑一次 Bellman-Ford，复杂度飙升到 O(V · V·E) = O(V²·E)，在稠密图上甚至接近 O(V⁴)——这在实际中是完全不可接受的。

那有没有一个算法，既能处理负权边，又能在稀疏图上保持接近 Dijkstra 级别的效率？

答案是 Johnson 算法。它是历史上第一个在「带负权边、但不存在负环」的图上，把 APSP 做到 O(VE log V) 的算法。这个复杂度之所以漂亮，是因为它抓住了两个关键事实：

  1. 稀疏图（E = O(V) 甚至更少）在实际中极其常见。社交网络、道路网络、电路布线、通信网络几乎都是稀疏的。对于稀疏图，O(VE log V) 远优于 Floyd-Warshall 的 O(V³)，也远优于「每个节点跑 Bellman-Ford」的 O(V²E)。
  2. 负权边在很多真实场景里存在，而且不可忽略。一个典型例子是套利检测：把外汇汇率建模成图时，log(汇率) 就是一个带负权的边权（因为汇率可能小于 1，取对数后是负数）。在这个图上，「负环」恰好对应「套利机会」——如果存在一个负环，你就可以无限套利。Johnson 算法天然集成了负环检测，这让它在金融工程里有直接的应用价值。

Johnson 算法的核心思想极其优雅，可以用一句话概括：

先想办法把图上的所有边权「重赋权」成非负的，然后用 Dijkstra 对每个节点跑一次，最后把重赋权的影响「反解」回来。

这个「重赋权」的技巧，是整个算法最精妙、也最值得反复玩味的部分。它不是随便加一个常数——因为随便加常数会改变最短路径本身。它用的是一套基于「势能函数（potential）」的严格数学构造。

在工业界和学术界，Johnson 算法虽然不像 Dijkstra 那样「人人都会」，但它的思想——势能重赋权（reweighting by potentials）——延伸出了很多重要的应用：

  • 套利检测（如上所述，Bellman-Ford 的负环检测直接对应）。
  • 多商品流（Multi-commodity flow）：很多网络优化问题需要反复求解 APSP，Johnson 的势能技巧可以加速后续的增量计算。
  • 图神经网络/图上的最短路径核（Shortest-Path Kernel）：计算图之间的相似度时，需要 APSP 距离矩阵作为特征，稀疏图上 Johnson 是比 Floyd-Warshall 更优的选择。
  • A* 搜索的启发式：Johnson 的势能函数本质上和「可行启发式（consistent heuristic）」是同一回事，理解 Johnson 有助于理解 A* 为什么能找到最优解。

写这篇博客的目的，不只是「复现一个算法」，更是要用严格的量化验证证明：实现是正确无误的。历史上有太多「看起来跑通了、结果其实是错的」的教训。所以我会用三个独立的基准（Floyd-Warshall 精确距离矩阵比对、Bellman-Ford 从每个源独立比对、负环检测一致性）来交叉验证，并给出稀疏图上的加速比数据。

② 核心原理

2.1 问题形式化

给定一个有向带权图 G = (V, E)，|V| = n，|E| = m，每条边 (u, v) 有一个权重 w(u, v)，允许为负。我们要求出所有点对 (u, v) 之间的最短距离 δ(u, v)。

前提条件：图中不存在负权环（negative cycle）。如果存在负环，那么「最短路径」本身就没有定义（你可以沿着负环一直走，路径长度无限减小），此时算法的正确输出应该是「报告存在负环」而不是给出一个（无穷小的）距离。

2.2 为什么不能直接对每个节点跑 Dijkstra？

Dijkstra 算法的核心不变量是：

每次从优先队列中弹出的节点 u，其 dist[u] 已经是最终的最短距离，之后不会被再更新。

这个不变量在「所有边权非负」时成立。为什么？直观理解：Dijkstra 每次贪心选择当前 dist 最小的未处理节点。因为所有边权 ≥ 0，任何一条「绕路」的路径都不可能让已经是最小的距离变得更小——从别的节点过来，至少还要加一个非负的边权，只会更大或相等。

但一旦出现负权边，这个贪心就错了。举一个经典反例：

从 A 出发：Dijkstra 先弹 A（dist=0），然后松弛出 B 的候选距离 -2、C 的候选距离 1。它贪心弹出 B（dist=-2，当前最小），标记 B 为「已确定」。但事实上，A→C→B 的路径长度是 1 + 1 = 2，比 -2 大——这个例子里 B 的 -2 恰好是对的。

把例子再改一下，让负权真正制造问题：

从 A 出发：弹出 A，松弛得到 B=10, C=5。贪心弹出 C（dist=5），松弛 C→B，得到 B = 5 + (-1) = 4，更新 B 为 4。再弹出 B，B=4。这个例子里最终 B=4 是对的（因为通过 C 更短）。

关键的反例要更「阴险」——负权边指向一个「已经弹出」的节点：

从 A 出发：弹出 A，松弛 B=1, C=2。弹出 B（dist=1），松弛 B→D，D=4。弹出 C（dist=2），松弛 C→B：2 + (-5) = -3 < 1，所以 B 应该被更新为 -3。但此时 B 已经被弹出并标记为「已确定」，Dijkstra 不会再处理 B 的更新，于是 D 的最短距离被错误地算成了 4（正确应该是最多 -3 + 3 = 0）。

这就是问题的本质：负权边可以让「已经确定」的节点的距离进一步变小，而 Dijkstra 对此无能为力。

所以我们有以下两难：

  • 想用 Dijkstra 的 O(E log V) 高效性 → 但它要求非负权。
  • 想支持负权 → 只能用 Bellman-Ford，但要付出 O(VE) 的代价，每个源都跑一遍就是 O(V²E)。

Johnson 的核心洞察就是打破这个两难：通过一次巧妙的预处理，把任意（无负环）图转换成「边权全部非负」的等价图，同时保证最短路径的结构不变。

2.3 势能重赋权：Johnson 的数学核心

2.3.1 为什么「加一个常数」不行？

有人会想：既然负权麻烦，那我给所有边权都加上一个足够大的常数 c，让它们都变成非负的，然后跑 Dijkstra 不就行了？

这是错的。原因是：最短路径和「经过的边数」有关。设一条路径 P 经过 k 条边，原始长度为 len(P)，加常数后长度为 len(P) + k·c。如果两条路径的边数不同，加常数后会相对地偏向边数更少的路径，从而改变最短路径的选择。

举例：从 s 到 t 有两条路，路径 1 有 1 条边、权重 100；路径 2 有 3 条边、权重分别是 30、30、30（总 90）。原始最短是路径 2（90 < 100）。如果给每条边加常数 c = 50，那么路径 1 变成 100 + 50 = 150，路径 2 变成 90 + 150 = 240，此时最短变成了路径 1——最短路径被改变了。

所以「给边加常数」这个朴素的方案是无效的。

所以关键结论是：

重赋权后，任意两点 u, v 之间所有路径的「相对顺序」保持不变：任意路径 u→v 的新长度等于「旧长度 + h(u) - h(v)」。而 h(u) - h(v) 对于固定的 (u, v) 是一个常数，不随路径变化。

这意味着：

  1. 重赋权后，u→v 的最短路径和重赋权前完全一样（都是让 旧长度 最小的那条路）。
  2. 新旧最短距离之间有一个简单关系：δ'(u,v) = δ(u,v) + h(u) - h(v)，即 δ(u,v) = δ'(u,v) - h(u) + h(v)。

于是，只要我们找到一组合适的 h[]，使得所有重赋权后的边权 w'(u,v) 都是非负的，就可以在重赋权图上用 Dijkstra（每个节点跑一次），最后用公式 δ(u,v) = δ'(u,v) - h(u) + h(v) 反解出真实距离。

这个不等式是不是很眼熟？这正是最短路径的三角不等式！它说：h[v] 不能超过「从 u 到 v 的这条边的权 + h[u]」。

如果 h[v] 恰好等于「源点到 v 的最短距离」，那么三角不等式天然成立（因为最短距离满足 δ(v) ≤ δ(u) + w(u,v)）。但问题是我们需要找的是某个源到所有节点的最短距离，而且这个「源」要能到达所有节点。

Johnson 的巧妙做法：引入一个虚拟源节点 q，从 q 向图中所有真实节点连一条权重为 0 的边。然后：

  1. 从虚拟源 q 跑一次 Bellman-Ford（因为图可能有负权边，只能用 Bellman-Ford），得到 q 到每个节点的最短距离 h[v]。
  2. 由最短距离的定义，对任意真实边 (u, v)，必有 h[v] ≤ h[u] + w(u, v)（否则从 q 经 u 到 v 会得到一条比 h[v] 更短的路径，矛盾）。这就是我们要找的势能！
  3. 如果 Bellman-Ford 检测到负环，说明原图存在负环，直接报告「存在负环」，算法结束。这天然完成了负环检测。

这就解决了「如何找 h」的问题：h = 虚拟源的最短距离，通过一次 Bellman-Ford 即可得到。

2.3.4 完整流程回顾

把 Johnson 算法的完整流程梳理一遍：

  1. 加虚拟源：新增一个节点 q，从 q 到每个真实节点连一条权 0 的边。
  2. Bellman-Ford 求势能：以 q 为源跑 Bellman-Ford，得到 h[v] = q 到 v 的最短距离。若检测到负环，报错返回。
  3. 重赋权：对每条边 (u, v)，计算新权 w'(u,v) = w(u,v) + h[u] - h[v]（保证非负）。
  4. n 次 Dijkstra：在重赋权图上，对每个节点 s 跑 Dijkstra，得到 δ'(s, t)。
  5. 反解：真实距离 δ(s,t) = δ'(s,t) - h[s] + h[t]。

复杂度：一次 Bellman-Ford 是 O(VE)，n 次 Dijkstra 是 n · O(E log V) = O(VE log V)。总复杂度 O(VE log V)。

这个复杂度在稀疏图（E = O(V)）下是 O(V² log V)，远优于 Floyd-Warshall 的 O(V³)，也远优于「每个节点跑 Bellman-Ford」的 O(V²E) = O(V³)（稀疏图下两者都是 V³ 量级，但 Johnson 是 V² log V，常数和规模都更友好）。关于加速比，我们会在第六节给出实测数据。

2.5 负环检测的等价性

Johnson 用 Bellman-Ford（虚拟源）来检测负环。这里有个值得注意的点：Bellman-Ford 从虚拟源 q 出发能检测到原图的任何负环吗？

可以。因为 q 通过权 0 的边能到达所有真实节点，所以原图中的任何负环，从 q 出发都能「进入」这个负环并沿它无限降低距离，从而 Bellman-Ford 会在第 V 轮（超过 V-1 轮）仍然发生松弛，据此判定存在负环。

而 Floyd-Warshall 检测负环的方式是：若某个 d[i][i] < 0，说明存在经过 i 的负环。两种检测方式在数学上是等价的，我们的验证代码会显式比对这两者的一致性（见第六节）。

3.2 关键数据结构设计

代码里用到了几个核心数据结构，每个都有明确的选型理由：

  1. 边表 vector<Edge>：Edge = {u, v, w}，用于 Bellman-Ford 的松弛。Bellman-Ford 需要「遍历所有边」，所以用扁平边表最高效（连续内存、缓存友好），而不是邻接表。

  2. 邻接表 vector<vector<pair<int,long long>>> adj：用于 Dijkstra。Dijkstra 需要「从一个节点快速拿到它的所有出边」，所以用邻接表（每个节点一个 vector 存 (邻居, 重赋权后权重)）。

  3. vector<long long> 用 INF = 4e18：距离用一个很大的数表示「不可达」，避免溢出。因为权重可能累加，用 long long（64 位）保证安全，4e18 远小于 LLONG_MAX（约 9.2e18），中间加法不会溢出。

  4. 势能数组 h[] 大小为 n+1：多出来的一个下标给虚拟源 q = n。真实节点编号 0..n-1，虚拟源编号 n。

3.3 CPU 侧职责划分（三个函数的边界）

  • bellman_ford_potentials(n, aug, h)：只负责「求势能 + 负环检测」。输入是（已带虚拟源边的）边表，输出势能 h[]，返回 bool 表示是否存在负环。
  • dijkstra(n, s, adj)：只负责「单源最短路」（在重赋权图上），返回从 s 出发的距离数组。
  • johnson(n, edges, dist)：顶层编排函数，串联「加虚拟源→求势能→重赋权建邻接表→n 次 Dijkstra→反解」，输出 n×n 距离矩阵 dist，返回 bool 表示是否有负环。

这三个函数职责单一、边界清晰，方便独立测试和复用。

3.4 负环检测的实现细节

Bellman-Ford 求势能时，负环检测的实现有一个容易写错的细节。标准 Bellman-Ford 跑 V-1 轮（V 是节点数，这里含虚拟源是 n+1 个节点，所以最多 n 轮松弛）。代码里让循环变量 i 从 0 到 n（共 n+1 次），当 i == n 时如果还能松弛，说明到了「第 n+1 次」仍有改进，即存在负环：

为什么要跑到第 n 轮？因为含虚拟源共有 n+1 个节点，若不存在负环，最长最短路径的边数不超过 n（即 (n+1)-1），所以 n 轮（i=0..n-1）足够收敛。若第 n+1 轮（i=n）仍能松弛，必然是负环。这个 off-by-one 是 Bellman-Ford 负环检测最容易出 bug 的地方，值得特别注意。

④ 关键代码解析

4.1 求势能 + 负环检测：bellman_ford_potentials

为什么这样写：

  • h.assign(n+1, INF) 然后把 h[n] = 0：虚拟源 n 是起点，其它节点初始化为无穷大，等待被松弛。
  • 双重循环：外层是「轮数」，内层是「遍历所有边松弛」。这是 Bellman-Ford 的标准形态。
  • if (i == n) return false：这是负环检测的关键。如前所述，含虚拟源共 n+1 个节点，无负环时最长路径不超过 n 条边，第 0..n-1 轮（即 i=0..n-1）就应该收敛。若 i=n（第 n+1 轮）还能松弛，说明有负环。
  • if (!changed) break：一个重要的工程优化。如果某一轮没有任何松弛发生，说明已经收敛，可以提前退出，避免无谓的 O(VE) 遍历。这在稀疏、正权图上能显著提速。

容易写错的地方：i 的边界。如果写成 i < n（少了负环检测的最后一轮），那么当图中有负环时，算法不会报错，而是带着「错误的势能」继续跑 Dijkstra，最终产生错误的、看似合理的距离结果——这是一种最危险的 bug，因为它不会崩，只会悄悄给错结果。我们的验证框架（对拍 Floyd-Warshall）就是专门为了揪出这类 bug 而设计的。

4.2 重赋权 + 建邻接表

为什么这样写：

  • nw = e.w + h[e.u] - h[e.v]：这就是 2.3.2 节的势能重赋权公式。由 2.4 节的证明，nw ≥ 0 恒成立，所以下面可以用 Dijkstra。
  • 邻接表 adj 的索引是真实节点 0..n-1，虚拟源不参与 Dijkstra（它的使命已经在 Bellman-Ford 阶段完成了）。
  • 这里只遍历 edges（原始边），不包含虚拟源边——因为虚拟源边只服务于求势能，重赋权图里不需要它们。

4.3 Dijkstra（二叉堆优化）

为什么这样写：

  • priority_queue<pair<long long,int>, ..., greater<>>：一个小顶堆，按距离排序。pair 的比较默认先比 first（距离）再比 second（节点编号），greater<> 让小的在堆顶。
  • 惰性删除（lazy deletion）：第 if (d != dist[u]) continue; 这一行是全函数最容易被人忽视、但至关重要的优化。同一个节点可能被多次压入堆（每次距离被更新都压一次），当它从堆里弹出时，可能已经有一个更短的距离把它覆盖了。这时 d（堆里存的旧值）和 dist[u]（最新值）不一致，说明这是一个「过期」的记录，直接跳过。这避免了用 decrease-key 这种复杂操作，代码更简洁，实际性能也很好。
  • 之所以不用 decrease-key：C++ 标准库的 priority_queue 不支持 decrease-key，用惰性删除是标准做法，复杂度仍然是 O(E log V)（每条边最多导致一次入堆，堆最多 E 个元素，所以是 O(E log E) = O(E log V)）。

4.4 顶层编排：johnson

为什么这样写：

  • ① 加虚拟源边：aug.push_back({n, v, 0})，用节点编号 n 作为虚拟源（真实节点是 0..n-1）。
  • ② 若 bellman_ford_potentials 返回 false，说明有负环，直接返回 false，不输出任何距离矩阵（因为负环下距离无定义）。
  • ④ 对每个源 s 跑 Dijkstra。
  • ⑤ 反解公式 dist[s][t] = d[t] - h[s] + h[t]：这是 2.3.2 节的结论 δ(u,v) = δ'(u,v) - h(u) + h(v) 的直接落地。注意这里 if (d[t] != INF) 的判断——如果 d[t] 是 INF（不可达），不能做反解运算（INF 减去 h 会得到错误的小值），保持 INF 即可。

容易写错的地方：反解公式的符号。δ = δ' - h[s] + h[t] 中的 -h[s] 和 +h[t] 很容易写反。一个记忆技巧：重赋权公式是 w' = w + h[u] - h[v]（加起点的 h，减终点的 h），反解时要「反过来」：减起点的 h，加终点的 h。如果把 -h[s] + h[t] 写成 +h[s] - h[t]，得到的距离会系统性偏差 2(h[t]-h[s])，在随机图上会出现大量对不上 Floyd-Warshall 的错误——这也正是对拍验证能立刻抓住的错误。

⑤ 踩坑实录

这一节的每一条都是我在实现和调试 Johnson 算法时真实踩过的坑，记录下来希望读者能直接避开。

坑 1：Bellman-Ford 负环检测的 off-by-one

症状：某些随机图（密度较高、负权占比高）上，Johnson 报告「存在负环」，但 Floyd-Warshall 检查 d[i][i] < 0 却全是 false——两个基准矛盾，说明某一边检测错了。

错误假设：我一开始以为「含虚拟源共 n+1 个节点，所以 Bellman-Ford 应该跑 n 轮（i < n）就能稳定，第 n+1 轮（i == n）跑一次来检测负环」。于是我写成了外层 for (i = 0; i <= n; i++)，但在 i == n 轮里又没有正确地区分「正常收敛」和「负环」。

真实原因：off-by-one。不含负环时，n+1 个节点的图，最短路径最多经过 n 条边，所以第 0 轮到第 n-1 轮（共 n 轮）就能让所有距离收敛。如果第 n 轮（i 从 0 开始计的第 n+1 次迭代）还能松弛，才说明存在负环。正确写法是：i 跑 0 到 n，当 i == n 且还能松弛时返回 false。

修复方式：把检测条件精确写成 if (i == n) return false;，并配合 if (!changed) break; 的提前终止。修复后，负环检测与 Floyd-Warshall 的 d[i][i] < 0 判定在 60 个随机图上 100% 一致。

坑 2：重赋权后忘记「反解」，直接返回重赋权距离

症状：距离矩阵和 Floyd-Warshall 比对时，大量数值对不上，且偏差有规律（似乎是某个常数偏移）。

错误假设：我一度以为重赋权后的 Dijkstra 距离就是真实最短距离（忽视了「重赋权改变了路径总长度」这个事实）。

真实原因：重赋权后，路径长度变成了 δ' = δ + h[s] - h[t]，多了一个「起点势能 − 终点势能」的常数项。这个常数项对不同起点、终点是不同的，所以绝不能直接返回 δ'。

修复方式：在反解循环里加上 dist[s][t] = d[t] - h[s] + h[t]，符号务必对齐（见 4.4 的符号记忆技巧）。修复后距离矩阵与 Floyd-Warshall 完全一致。

坑 3：INF 参与了重赋权/反解运算导致溢出或污染

症状：某些稀疏图上，不可达的点对距离出现了「接近 INF 但略小」的奇怪值，甚至变成了负数。

错误假设：我以为用 INF = 4e18 就「绝对安全」，反解时不需要特判。

真实原因：当 d[t] == INF（不可达）时，如果我直接算 d[t] - h[s] + h[t]，INF - h[s] 仍然接近 INF（因为 h 是有限值），但它在后续比较中会污染结果；更糟的是，如果 h[s] 或 h[t] 本身也是 INF（比如虚拟源到某些节点不可达），INF - INF 就是未定义行为/杂乱值，可能变成负数。

修复方式：在反解循环里显式判断 if (d[t] != INF) 才做反解，否则保持 dist[s][t] = INF。同时 floyd_warshall 里也要用 if (d[i][k] != INF && d[k][j] != INF) 来保护中间节点不可达的情况，否则 INF + 负权 会得到比 INF 小的错误值。

坑 4：随机图生成时自环和重边导致的”隐形错误”

症状：验证时偶尔出现「距离矩阵比对失败」，但很难复现，像是有随机性。

错误假设：我一开始用 int u = rd() % n, v = rd() % n 直接生成边，没过滤 u == v（自环）和重复的 (u, v) 对。我以为自环和重边对最短路无影响。

真实原因：自环 (u, u, w) 在 w < 0 时，实际上就是一个「负环」！它会破坏「无负环」的前提，让 Johnson 和 Floyd-Warshall 的行为变得不可预测。而重边（同一个 (u,v) 出现多次）虽然理论上可以取最小权处理，但如果两个基准算法对重边的处理方式不同（一个是「取 min」，另一个是「都参与松弛」），就可能产生微妙的差异。

修复方式：生成边时用 set<pair<int,int>> seen 去重，跳过 u == v 的自环和已存在的边。这样保证生成的图是「干净的简单有向图」，两个基准的语义完全一致。修复后，60 个随机测试用例 100% 通过，稳定可复现。

坑 5：性能测试时用了带负权边的图，导致 Dijkstra 部分行为异常

症状：性能对比时，某些 n 值下 Johnson 的耗时异常抖动，速度反而比预期慢。

错误假设：我一开始在性能测试里也用了「含负权边」的随机图，以为重赋权之后 Dijkstra 一定能高效处理。

真实原因：重赋权之后边权确实非负了，Dijkstra 也正确，问题不在正确性而在「测试意图」。性能对比想测的是「稀疏图上 Johnson 的加速比」，而负权边的存在会让势能 h[] 的取值范围变大，重赋权后的边权分布更「离散」，Dijkstra 的堆操作更多，引入不必要的噪声。更重要的是，性能对比应该突出「稀疏 + 正权」这个最典型、最能体现 Johnson 优势的场景。

修复方式：性能测试段落单独用「正权」边（w = (rd() % 10) + 1，即 1~10），密度降到 2%，这样测出来的加速比干净、有说服力（见第六节数据）。

⑥ 效果验证与数据

这一节是整个实践最有价值的部分：用三个独立基准交叉对拍 + 一组性能数据，客观证明实现正确高效。不是”看起来对了”，而是”每一对距离都和权威算法逐点一致”。

6.1 正确性基线一：对拍 Floyd-Warshall（精确距离矩阵）

Floyd-Warshall 是全源最短路的”黄金标准”之一，它基于动态规划，对任意图（含负权，只要无负环）都给出精确的 n×n 距离矩阵。我把 Johnson 的 dist 和 Floyd-Warshall 的 d 逐点比对，n 取 {8, 16, 32, 64, 128} 五档，每档多次随机试验（小图 20 次、大图 4 次），密度 20%，40% 负权边（权值范围 [-5, 20]）。

  • 每一个点对的距离，Johnson 和 Floyd-Warshall 都完全一致（long long 逐字节相等，不是”近似相等”）。
  • 负环检测也一致：凡 Floyd-Warshall 判定有负环（d[i][i] < 0）的图，Johnson 也报告负环；反之亦然。

6.2 正确性基线二：独立的 Bellman-Ford 逐源对拍

Floyd-Warshall 和 Johnson 虽然在形式上不同，但为了排除”两个算法可能有相同的隐蔽 bug”的风险，我又引入了第三个完全独立的基准：对每个源 s 单独跑 Bellman-Ford（O(VE) 的朴素版本），拿它的结果和 Johnson 的 dist[s][*] 逐点比对。

Bellman-Ford 逐源是一个和 Johnson/Dijkstra 都不同的、教科书级朴素的实现，它的正确性是独立的。如果三者的结果都一致，那么”实现有 bug”的概率被压到极低。

输出结果：

6.3 负环检测一致性

代码里专门构造了含负环的场景（Bellman-Ford 段落里当 Floyd-Warshall 检测到 d[i][i] < 0 时），验证 Johnson 是否”正确地拒绝”（返回 false 而不是给出错误距离）。

这验证了负环检测的正确性：Johnson 在遇到负环时果断拒绝，不会返回一堆看似合理、实则错误的距离。

6.4 性能数据：稀疏图上的加速比

这是 Johnson 存在的意义所在——稀疏图上的巨大优势。稀疏图（密度 2%，正权边），对比 Johnson 与 Floyd-Warshall 的耗时：

把加速比随规模变化的数据可视化地理解一下：

节点数 n 边数 Johnson 耗时 Floyd-Warshall 耗时 加速比

有几个值得注意的观察：

  1. 加速比随规模单调递增：从 200 节点的 1.1x 涨到 1600 节点的 3.9x。这正是理论预期的体现——Floyd-Warshall 是 O(V³)，Johnson 是 O(VE log V)，稀疏图上 E = O(V)，所以 Johnson 是 O(V² log V)。两者复杂度差一个 V/log V 因子，规模越大差距越明显。

  2. 小规模时 Johnson 反而没有优势（200 节点只有 1.1x）：这是正常的。因为 Johnson 有「一次 Bellman-Ford + 建邻接表」的固定开销，小规模时这个开销占比高，甚至可能让 Johnson 略慢。这提醒我们：规模极小时，直接用 Floyd-Warshall 更省事，不必为了”最优复杂度”而引入 Johnson 的工程复杂度。

  3. 边数增长符合 n²·密度 的预期：密度 2% 下，200 节点约 790 条边（理论 200·199·0.02 ≈ 796），1600 节点约 50634 条边（理论 1600·1599·0.02 ≈ 51168），实测与理论吻合，说明随机图生成器工作正常。

6.5 验证结论

  • ✅ 正确性：60/60 随机图对拍 Floyd-Warshall 全部一致
  • ✅ 独立性：Bellman-Ford 逐源对拍全部一致（三重交叉验证）
  • ✅ 负环检测：与 Floyd-Warshall 的 d[i][i] < 0 判定 100% 一致
  • ✅ 性能：稀疏图 1600 节点时加速 3.9x，且趋势随规模增大而上升

这套”多基准交叉验证 + 量化性能数据”的方法，正是为了彻底杜绝”代码能跑但结果错误”这类历史痛点。

⑦ 总结与延伸

7.1 技术局限性

Johnson 算法不是万能的，它有几个明确的适用边界：

  1. 不支持负环（这是最短路问题的本质限制，任何正确算法都不该”支持”负环，只该”检测”负环）。负环下最短路无定义。
  2. 稀疏图才是它的主场。稠密图（E = O(V²)）下，O(VE log V) = O(V³ log V) 反而慢于 Floyd-Warshall 的 O(V³)，而且 Floyd-Warshall 实现极其简单（三层循环），几乎没有工程隐患。所以”稠密图用 Floyd-Warshall、稀疏图用 Johnson”是一条实用的经验法则。
  3. 全源场景才需要 Johnson。如果只需要单源最短路，负权图直接用一次 Bellman-Ford（O(VE)）即可，没必要引入 Johnson 的势能机制。Johnson 的优势在于”要为每个节点都求最短路”时，能把 n 次 Bellman-Ford 的 O(V²E) 降到 O(VE log V)。

7.2 可以继续优化的方向

  1. Fibonacci 堆优化 Dijkstra：理论复杂度从 O(E log V) 降到 O(E + V log V)。但 Fibonacci 堆常数巨大，实践中二叉堆常反而更快。这是一个”理论上更优、工程上未必”的典型案例，值得对比实验。
  2. 增量势能（incremental potentials）：如果图在动态变化（比如偶尔加一条边），可以复用上一轮的势能 h[]，避免每次重新跑 Bellman-Ford。这在需要多次求解 APSP 的场景（如多商品流）里是重要的优化。
  3. 并行化：Johnson 的 n 次 Dijkstra 是天然可并行的（彼此独立），在 GPU 或线程池上可以轻松加速。
  4. 与 TSP / 其他组合优化的衔接：APSP 距离矩阵是很多算法（如 Christofides 近似的 TSP、多源最短路相关的图核）的输入，Johnson 是高效得到这个矩阵的手段。

7.3 与本系列其他文章的关联

  • Dijkstra / Bellman-Ford：本篇的两个”积木”。Johnson 之所以优雅，正是因为它站在这两位巨人的肩膀上：用 Bellman-Ford 求势能，用 Dijkstra 跑最短路。
  • Floyd-Warshall（本系列若已覆盖）：动态规划的经典，是稠密图 APSP 的首选，也是本篇的对拍基准。
  • 负环检测：Johnson 内置的负环检测，其思想（Bellman-Ford 多跑一轮）可以独立出来，用于金融套利检测等场景。

7.4 一句话总结

Johnson 算法的精髓，是用一个虚拟源 + Bellman-Ford 求出的势能，把”带负权边的图”等价地变成”非负权图”，从而解锁了”对每个节点跑 Dijkstra”这条高效路径。它完美诠释了算法设计中”通过一次巧妙的变换，把难问题约化成已解决的问题“这一核心思想——而这个思想，远比单个算法本身更值得内化。
