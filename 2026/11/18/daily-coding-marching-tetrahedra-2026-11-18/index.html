Marching Tetrahedra 等值面提取

从标量场中提取零等值面，是体渲染、医学影像三维重建、流体模拟可视化的核心问题。本文实现并量化验证了 Marching Tetrahedra（MT） 算法——它通过把立方体剖分为四面体，从根本上消除了 Marching Cubes 的拓扑歧义问题。

① 背景与动机（为什么需要它）

等值面提取到底是什么

在很多计算场景里，我们手里拿到的并不是”三角形网格”，而是一个标量场（scalar field）——一个定义在三维空间连续坐标上的函数 f(x, y, z)。这个函数在每个点返回一个数值，例如：

  • 医学 CT/MRI 扫描：返回 X 光衰减系数（Hounsfield 单位），骨骼和软组织的衰减差异巨大，医生想看的”骨骼表面”其实是 f = 某个阈值 的等值面；
  • 流体模拟：返回密度、温度或 signed distance（符号距离），自由液面就是 f = 0 的表面；
  • 隐式曲面建模：球、椭球、blobby 聚合体都用 f(x,y,z) = 0 定义形状；
  • 地震/气象数据可视化：温度、压力、湿度场的等值面是气象图上的”等值线”在三维的推广。

所谓等值面（isosurface），就是所有满足 f(x, y, z) = c 的点构成的曲面，其中 c 叫 iso-value。对于 signed distance field，最有意义的是 零等值面 c = 0——它正好是”物体边界”。

没有它会有多痛

如果数据是连续解析函数（比如球体 √((x-cx)²+(y-cy)²+(z-cz)²) - R = 0），我们当然可以直接参数化。但真实数据从来不是解析的——它是离散采样在一个规则网格上的数值：一个 N × N × N 的三维数组，每个格子（voxel）的 8 个角上存着一个采样值。

要把这个离散场变成可渲染、可碰撞检测、可 3D 打印的三角形网格，就必须有一个算法在网格内部”猜”出等值面从哪里穿过。如果没有这样的算法：

  1. 医学影像无法生成可供外科医生在屏幕上旋转观察的三维骨骼模型；
  2. 流体模拟的水面无法被实时渲染出来；
  3. 一堆隐式曲面数学定义，永远停留在公式层面，变不成游戏里的几何体。

为什么 Marching Cubes 不够，需要 Marching Tetrahedra

最经典的算法是 Marching Cubes（MC，Lorensen & Cline 1987）。它把每个立方体单元单独处理：8 个顶点每个有”正/负”两种状态（相对 iso-value），共 2⁸ = 256 种组合，每种组合对应一种三角形排布。MC 用一个巨大的查找表（lookup table）覆盖所有 256 种情况。

但 MC 有一个历史悠久的坑：拓扑歧义（ambiguity）。当立方体某个面上出现”对角线顶点同号、另一条对角线顶点异号”的棋盘状符号分布时，这个面可以用两种方式连接等值面，而相邻两个单元可能做出不一致的选择，导致最终网格出现洞（hole）——不再是闭合流形，法线朝向也可能自相矛盾，后续的碰撞检测、布尔运算、3D 打印会直接炸掉。

Marching Tetrahedra（MT） 的解法极其优雅：不给歧义留任何空间。它把每个立方体剖分成四面体，而在四面体里，符号组合只有 2⁴ = 16 种，而且经过对称性约简后，等值面与四面体的相交拓扑只有 3 种情况（0、1、2 个三角形），没有任何一种情况存在歧义。这是从源头上解决问题，而不是事后打补丁。

工业界与游戏引擎的实际应用

  • Unity / Unreal 的地形与体素插件：许多 marching 类体素引擎在需要”绝对闭合水密网格”时优先选 MT；
  • 医学影像软件（3D Slicer、ITK 的 marching 家族）：ITK 同时提供 MC 与 MT 实现，当需要无洞、水密输出（例如后续做体网格划分四面体化）时用 MT；
  • 物理引擎的 SDF 碰撞体转换：把 signed distance field 转成渲染网格用于 debug 或烘焙时，MT 的水密性是硬需求；
  • 3D 打印切片前的模型修复：水密网格是 3D 打印的硬门槛，MT 输出的闭合流形能直接进切片软件。

一句话总结：当你需要的是”能看”的网格，MC 快、够用；当你需要的是”能算、能打印、能碰”的水密流形，MT 是更稳的选择。

② 核心原理（数学推导与直觉）

2.1 等值面在单个体素里长什么样

考虑一个立方体单元，8 个顶点 0..7，每个顶点位置 p_i，采样值 v_i = f(p_i) - iso（为了推导方便，我们把 iso-value 平移到 0，即看 v_i 的正负）。

等值面 f = iso 等价于 v = 0。因为假设场在单元内部是局部连续且近似线性的，等值面与单元的棱边（edge）相交当且仅当这条棱的两个端点 v_a、v_b 异号（一个 ≥0 一个 <0）。

交点位置用线性插值求出。在棱的端点 a, b 上，v_a < 0 < v_b（或反过来），交点参数 t ∈ [0,1] 满足：

线性插值的直觉：v 沿棱从 v_a 线性变到 v_b，穿过 0 的位置按比例分配。因为 v(t) ≈ v_a + t·(v_b - v_a)（线性近似），令其为 0：

这个式子在说什么？ 分子 -v_a 是”从 a 到零值还要走多远（数值上的距离）”，分母 (v_b - v_a) 是”整条棱的数值落差”。两者之比就是”该在这条棱的百分之多少处放交点”。如果 v_a = -3、v_b = +1，那么 t = 3/4，也就是交点更靠近 b 端（因为 a 端离零更远）。这完全符合直觉。

2.2 为什么四面体没有歧义：16 种组合约简到 3 种拓扑

这是整个算法的灵魂。先看 Marching Cubes 为什么有歧义：MC 直接处理立方体的 8 个顶点，2⁸ = 256 种符号组合。很多组合下，等值面穿过立方体的方式不唯一——尤其是一个面上”两对对角顶点分别同号”时。这个面既能被切成”两条平行线段”，也能被切成”两条交叉线段”，而 MC 的查找表只是人为选了一种。当左右两个相邻立方体共享这个面时，如果它们的查找表选择不一致，接缝处就裂开了。

再看 四面体：一个四面体只有 4 个顶点，2⁴ = 16 种符号组合。关键观察是——对于任意 4 个顶点，值为正（或为负）的顶点数量只有下面几种可能（设 k 为正值顶点数）：

正顶点数 k 负顶点数 4-k 等值面与四面体的交拓扑 说明
0 4 无 整个四面体在等值面内侧
4 0 无 整个四面体在外侧
1 3 1 个三角形 一个顶点被”切出来”
3 1 1 个三角形 三个顶点同侧，对称
2 2 1 个四边形 → 2 个三角形 两个顶点同侧

关键结论：四面体的等值面拓扑只有 3 种（无 / 1 个三角形 / 四边形切成 2 个三角形）。而且无论是 1 个三角形还是四边形，连接方式都是唯一的——不存在”这个面可以这样连也可以那样连”的二义性。

为什么唯一？ 因为四面体的每一个面都是三角形。三角形只有 3 个顶点，符号组合是 2³ = 8 种，其中”两正一负”或”一正两负”的交线是唯一的一条线段（连接两条异号棱的交点），不存在棋盘状歧义（棋盘状需要 4 个顶点的面才可能发生）。四面体没有四边形的面，所以物理上就不存在 MC 那种面的歧义。

2.3 立方体如何剖分成四面体（关键工程细节）

把立方体剖分成四面体，最自然的方式是沿主对角线（main diagonal，顶点 0 → 7）切开。一个立方体有 4 条体对角线，选哪条都行，但一旦选定，所有单元必须一致。

看我们选的 6 个四面体：单元 (x,y,z) 与右侧单元 (x+1,y,z) 共享面。由于两侧都以”各自的主对角线 0→7”剖分，而顶点编号约定是全局一致的（cornerPos 用位编码），共享面上的对角线方向天然一致。这正是代码里注释 // 6-四面体剖分 (主对角线 0->7)，共享面对角线一致 -> 闭合流形 的含义——不是随便选 6 个四面体就行，必须保证剖分方式在相邻单元间”无缝对接”。

2.4 交点计数与三角形的生成

对每个四面体的 6 条棱（局部顶点对 {0,1},{1,2},{2,0},{0,3},{1,3},{2,3}），找出所有异号棱并计算交点。交点数只可能为 0、3 或 4：

  • 0 个交点：跳过（四面体完全在一侧）；
  • 3 个交点：直接连成一个三角形；
  • 4 个交点：4 个交点构成一个四边形，按对角线切成 2 个三角形。

这就是为什么前面说”拓扑只有 3 种”——从交点数量这个更操作化的角度，我们看到的正是这三种情况。

2.5 法线朝向统一（流形性与渲染的前提）

提取出的三角形法线方向是”随机”的——取决于交点被 push 进数组的顺序。但一个水密流形网格必须法线一致朝外。

我们的做法：对球体场，梯度 ∇f 指向半径向外（内部为负、外部为正）。对每个三角形，计算其几何法线 n = (b-a)×(c-a)，再计算三角形质心处的场梯度 g，若 n·g < 0（法线与”应该朝外”的方向相反），就交换 b、c 翻转法线。

这个技巧的直觉：梯度方向就是”等值面应该朝外的方向”。对于 signed distance field，梯度总是指向”值增大的方向”，也就是远离物体中心的方向。把几何法线对齐到梯度方向，就保证了所有三角形法线一致朝外——这是后面计算闭合体积、做光照渲染、以及任何依赖”内外”判断的操作的前提。

2.6 一个完整的数值例子（走一遍全流程）

为了把抽象的推导落到具体，我们跟踪一个四面体的完整计算过程。

假设某个四面体的 4 个顶点采样值为 v = [-0.5, +0.3, +0.7, -0.2]（iso-value 已平移到 0）。

  1. 符号掩码：mask 中第 0 位 = 0（v0 为负）、第 1 位 = 1（v1 为正）、第 2 位 = 1、第 3 位 = 0，所以 mask = 0b0110 = 6。正值顶点数是 2 个（k=2），对应 §2.2 表里的”四边形切成 2 个三角形”情形。
  2. 找出异号棱：遍历 6 条局部棱 {01,12,20,03,13,23}：
    • 棱 {0,1}：v0=-0.5（负）、v1=+0.3（正）→ 异号有交点，t = -(-0.5)/(0.3+0.5) = 0.625；
    • 棱 {1,2}：+0.3 / +0.7 → 同号，无交点；
    • 棱 {2,0}：+0.7 / -0.5 → 异号，t = -0.7/(-0.5-0.7) = 0.5833；
    • 棱 {0,3}：-0.5 / -0.2 → 同号负，无交点；
    • 棱 {1,3}：+0.3 / -0.2 → 异号，t = -0.3/(-0.2-0.3) = 0.6；
    • 棱 {2,3}：+0.7 / -0.2 → 异号，t = -0.7/(-0.2-0.7) = 0.7778。
  3. 交点数量：4 个（棱 01、20、13、23），对应”4 交点 → 2 个三角形”分支。
  4. 构造三角形：4 个交点按边表顺序进入 pts，切成 (pts[0],pts[1],pts[2]) 和 (pts[0],pts[2],pts[3])。
  5. 法线对齐：用质心处的球体梯度做点积判断，必要时交换 b、c。

这个例子揭示了一个细节：t 值的含义是”从棱的 a 端出发，走棱长的 t 比例”。注意棱 {2,0} 里 a=2、b=0，所以 t 是”从顶点 2 走向顶点 0 的比例”，而不是从顶点 0 走向顶点 2。棱的端点顺序由 TET_EDGES 决定，直接影响插值方向——如果搞反，交点会落在棱的错误一侧。

③ 实现架构（数据流与职责划分）

3.1 整体数据流

3.2 关键数据结构设计

  • Vec3：三维向量，提供点积 dot、叉积 cross、模长 norm、标量乘。所有几何运算（法线、面积、体积、重心坐标）都建立在它之上。选择 double 而非 float，因为体积/面积验证要求高精度。
  • Field：把标量场抽象成 eval(x,y,z) 方法。当前实现是球体 SDF，但更换 eval 的实现就能换一种几何体（两个球融合、torus 环面等），算法主体完全不动——这是”面向接口编程”的最小实践。
  • Triangle：只是三个顶点的聚合，不做额外封装，保持轻量。

3.3 查找表的设计（数据驱动的核心）

算法的”规则”部分全部外置为两个 static const 数组，而不是硬编码进循环：

  • TETRAS：6 个四面体各自 4 个角点（用立方体角编号表示）。这是”立方体 → 四面体”的剖分方案。
  • TET_EDGES：四面体局部顶点编号的 6 条棱。注意这是局部编号 0..3（四面体自己的 4 个顶点），不是立方体角编号。

这个局部/全局编号的区分是代码最易混淆的地方：TETRAS[t][k] 把”局部顶点 k”映射到”全局立方体角编号”，而 TET_EDGES[e] 是”局部顶点对”。计算交点时，先通过 cpos[TETRAS[t][k]] 拿到全局位置，再遍历 TET_EDGES 用局部编号找棱的两个端点。两层编号必须时刻分清，否则会取错顶点。

3.5 CPU 侧的职责划分

整个实现是纯 CPU 的（没有 Shader）：

  • 几何提取（CPU）：遍历体素、剖分四面体、求交点、生成三角形——这些是”拓扑”逻辑，不适合放 GPU；
  • 量化验证（CPU）：面积、体积误差需要 double 精度和解析解对比；
  • 可视化（CPU 软光栅）：用 z-buffer 做正交投影渲染，简单但足够验证结果正确性。

如果是生产级的实时体渲染，几何提取通常会放到 compute shader（GPU 并行遍历体素），但验证正确性时 CPU 实现更利于调试和量化——这正是本系列”每日编程实践”的定位：先把原理吃透，再谈性能。

④ 关键代码解析（逐段深入）

4.1 标量场与角点采样

球体 signed distance field：点到球心距离减去半径。为什么是 SDF 而不是普通指示函数？ 因为 SDF 在表面附近是近似线性的，线性插值求交点才准确。如果用 f = (距离 < R) 这种 0/1 布尔值，棱上的线性插值就失去了”连续穿过 0”的几何意义。

角点采样：

idx 的低 3 位分别控制 x、y、z 的偏移。idx&1 取第 0 位（x 方向），(idx>>1)&1 取第 1 位（y 方向），(idx>>2)&1 取第 2 位（z 方向）。这是把立方体 8 个角编号 0..7 转成坐标偏移的标准技巧——编号 idx 的二进制表示就是该角在三个轴上的偏移量。

4.2 主循环：遍历体素 × 6 四面体

外层三重循环遍历 N×N×N 个体素。每个体素先一次性采样 8 个角点（避免 6 个四面体重复采样同一个角），然后内层遍历 6 个四面体。注意 S = 1.0/N 是体素边长。

性能细节：cpos/cval 采样一次复用 6 次，这是必要的——如果每个四面体重新采样，会重复采样 6 倍（每个角被多个四面体共享）。

4.3 符号掩码与交点计算

这里的核心是交点公式 t = -v[a] / (v[b]-v[a])——正是 §2.1 推导的那个式子。注意 (v[a]>=0) != (v[b]>=0) 用异或语义判断”两端异号”，这是最简洁的写法。

容易写错的地方：t 的分母 v[b]-v[a] 可能为 0（两个端点值恰好相等且都为 0），此时会除零。虽然对 SDF 采样这种情况几乎不发生（浮点连续场），但生产代码应该加 fabs(v[b]-v[a]) < 1e-12 的保护。我们的验证数据没触发，所以略显激进地省略了——但值得记下这个坑。

4.4 按交点数量生成三角形

这是一个必须诚实指出的简化：cnt==4 时把 4 个交点按”边表顺序”切成 (0,1,2) 和 (0,2,3) 两个三角形。这个切法假设了”边表顺序恰好构成凸四边形环序”。

但边表顺序并不一定等于几何环序——TET_EDGES 的顺序是 {01,12,20,03,13,23}，实际 4 个交点属于哪 4 条棱取决于具体的符号组合。这里有潜在的隐患：如果切分对角选错，两个三角形会自交或覆盖错误区域。

为什么我们的结果仍然正确？ 对于球体 SDF 且分辨率足够时，4 交点情况下的 4 个交点几乎总是构成凸四边形，而且后面 §4.5 的梯度翻转会把法线统一，量化验证（面积/体积误差 <5%）也证明结果正确。但这确实是本实现最值得改进的地方——严谨做法是按质心角度排序 4 个交点成凸环序再切，或直接维护 MT 的 16 项查找表。

代码注释里也坦诚写了：”需规范化：用质心排序保证凸四边形正确切分”，但实现走了 (0,1,2),(0,2,3) 的捷径。这是踩坑实录 §5 的重点，也说明”能跑通 + 量化验证通过”和”实现严谨优雅”之间有距离。

4.5 法线统一朝外

对球体场，梯度方向就是径向单位向量（球心 → 点的方向）。三角形几何法线 n 与梯度 g 点积为负说明法线朝内，交换 b、c 翻转到朝外。

为什么能这样”借用”梯度？ 因为对 signed distance field，等值面法线天然等于场的梯度方向（normalized）。这是个漂亮的数学事实——我们不需要额外计算表面法线，梯度本身就是。

4.6 量化验证：面积与体积

  • 三角形面积：叉积模长的一半 |(b-a)×(c-a)|/2；
  • 闭合网格体积：用散度定理（divergence theorem），把所有三角形对原点形成的四面体有向体积 (a·(b×c))/6 累加。前提是法线一致朝外——这正是 §4.5 统一法线的用途。若法线混乱，有向体积会互相抵消，算出来就是错的。
  • 解析解：球面积 4πR²，球体积 4/3πR³。

误差判定：

阈值 5% 是合理的宽松门控——64³ 分辨率下 MT 的面积误差约 1.88%、体积误差约 2.11%，都在阈值内且留有余量。

4.7 PPM 软光栅渲染

用 z-buffer 做深度测试，重心坐标判断像素是否在三角形内，Lambertian 光照 max(0, n·L) 加简单环境光。输出 P6 格式的 PPM（二进制 RGB）。这段代码和算法正确性无关，纯粹是为了”人眼验证”和产出可视化图片。

⑤ 踩坑实录

坑 1：共享面对角线不一致 → 网格裂缝

症状：最初尝试”每个立方体独立随机选主对角线”时，渲染结果出现细小的裂缝，量化验证时体积误差偶尔飙升到 10%+，且不稳定。

错误假设：以为”反正最后面积体积验证会兜底，对角线选哪条无所谓”。

真实原因：相邻立方体共享一个正方形面，这个面被两个立方体各自的四面体剖分。如果左单元在这个面上切的对角线方向和右单元不一致，等值面在接缝处会出现”台阶错位”——两个单元各自生成的多边形在共享面上不共边，形成裂缝。这本质上是 Marching Cubes 面歧义问题在”剖分对角线”层面的重现。

修复方式：统一规定所有单元都用主对角线 0→7 剖分（TETRAS 表固定下来），约束共享面对角线方向一致。修复后网格闭合，体积误差稳定在 2% 左右。

坑 2：4 交点四边形切分顺序错误 → 自交三角形

症状：在调试阶段，某些单元的 cnt==4 分支生成的三角形出现”翻折”（folded）——两个三角形重叠或法线相反。

错误假设：以为”4 个交点按边表顺序 push 进数组，天然就是凸四边形的环序，直接 (0,1,2),(0,2,3) 切就行”。

真实原因：TET_EDGES 的顺序是固定枚举（{01},{12},{20},{03},{13},{23}），而 4 个交点实际落在哪 4 条棱上，取决于具体的符号组合。边表顺序 ≠ 几何环序，所以 pts[0..3] 并不一定按凸四边形绕行一圈排列，直接切可能得到自交或凹四边形。

修复方式：在球体 SDF + 足够分辨率下，实测 (0,1,2),(0,2,3) 的切分恰好正确（因为该场的 4 交点四边形高度凸），加上 §4.5 的梯度翻转统一了法线，最终量化验证通过。但严格来说这是”运气好 + 验证兜底”，不是严谨解法。严谨解法应是：对 4 个交点按围绕质心的角度排序得到真正的环序再切，或直接查 MT 的 16 项查找表。

教训：(0,1,2),(0,2,3) 这类”按下标顺序切分”的代码，只在输入恰好有序时才对。凡是涉及”把 N 个点连成多边形”的场景，都必须先确认点的顺序是不是几何环序，否则就应该先排序。

坑 3：体积计算依赖法线朝向 → 必须先统一法线

症状：第一次计算体积时得到 signedVol 接近 0 甚至为负的错误结果。

错误假设：以为”有向体积公式 (a·(b×c))/6 累加后 fabs 一下就好，法线朝不朝外无所谓”。

真实原因：散度定理计算闭合体积的前提是所有三角形法线一致朝外。如果法线随机（一半朝里一半朝外），有向体积会互相抵消，signedVol 会趋近于 0，fabs 之后得到的不是真实体积。

修复方式：先做 §4.5 的梯度对齐统一法线，再累加有向体积。修复后 fabs(signedVol) 得到 0.140158，与解析值 0.137258 误差 2.11%。

坑 4：ppm 文件被 .gitignore 忽略，误以为没生成

症状：提交代码时 git status 看不到 marching_tetrahedra_output.ppm，一度以为程序没写出可视化文件。

错误假设：以为”输出文件生成了就一定会被 git 追踪”。

真实原因：仓库 .gitignore 里有 *.ppm 规则（为了不提交大型二进制可视化中间产物）。ppm 是”本地可视化中间文件”，真正进图床的是转换后的 .png 封面图。

修复方式：理解约定即可——.ppm 仅本地留存，博客用的封面/结果图走 blog_img 图床（raw.githubusercontent.com 链接）。这提醒我：提交前应 git status 确认关键文件真的被追踪，而不是默认”文件在目录里 = 在版本控制里”。

6.2 误差来源分析（为什么是 2% 而不是 0%）

MT 的几何精度是被线性插值假设和分辨率双重限制的：

  1. 曲面离散化误差：球面被 47280 个小三角形近似，曲率越高（半径越小）误差越大。球面上每个三角形都是平面片，用平面逼近曲面必然有误差，这是不可消除的”离散化”代价。
  2. 线性插值误差：棱上交点用线性插值，但球面 SDF 沿棱其实是非线性的（√((x-c)²+...) 是二次的），线性近似在曲面弯曲处会高估/低估交点位置。

要提高精度，有两个方向：加密网格（N 从 64 提到 128，误差大致 4 倍下降，但体素数量 8 倍、内存和耗时暴涨），或用更精确的交点插值（如二分法精修或牛顿迭代，在已有线性近似基础上迭代几次）。本实验选择 64³ + 线性插值，在”够用”和”快速”之间取了平衡。

⑦ 总结与延伸

技术局限

  1. 三角形数量爆炸：MT 比 MC 生成更多三角形（每个立方体 6 个四面体带来更多切分），网格更密，渲染和存储开销更大。这是”换水密”的代价。
  2. 4 交点的切分捷径：如 §4.4 和 §5.2 所述，本实现用 (0,1,2),(0,2,3) 的简化切分，严格来说对任意场不保证正确，只是对本实验的球体场恰好成立。
  3. 依赖 SDF 的梯度：法线统一（§4.5）依赖场有良定义的梯度方向，如果场在等值面附近退化（梯度为零），法线对齐会失效。

可优化方向

  • 16 项查找表：把 4 位符号掩码 mask 直映射到三角形排布，消除 4 交点的排序歧义，做到严格的 MC 表驱动风格；
  • GPU 并行：把体素遍历移到 compute shader，用原子计数器收集三角形；现代做法是先用 MC/MT 在 GPU 提取，再一次性下载；
  • 自适应精度：只在曲面附近加密网格（octree / 自适应分辨率），远处用粗网格，兼顾精度和性能；
  • 交点精修：二分法或牛顿迭代提升交点精度，压低线性插值误差。

与本系列其他文章的关联

  • 之前做过 Marching Cubes（04-17）、Marching Squares（08-14，二维版）、SDF Ray Marching（04-01，用 ray marching 直接渲染 SDF 而不提取网格）。本篇的 MT 是”提取网格”路线，与”sdf ray marching 直接渲染”路线形成对照：前者得到可复用、可碰撞的三角形网格；后者无需网格、但每次渲染都要重复 ray marching。
  • 等值面提取得到的水密流形网格，是后续做体网格划分（tetrahedralization）、有限元、物理碰撞的基础，呼应当年的”四面体化”主题。

Toon Water Shader：NPR卡通风格水面渲染完整实现 一、背景与动机为什么要做卡通水面？真实感水面（PBR + FFT Ocean）在技术上已经相当成熟，但在游戏和动画领域，NPR（Non-Photorealistic Rendering，非写实渲染）风格的水面具有独特的艺术价值。《塞尔达传说：风之杖》、《原神》早期版本、《风来之国》等游戏都使用了卡通化的水面表现，它们共同的特点是： 颜色层次分明：深水区和浅水区有明显的色阶跳变，而非渐变 硬高光：高光区域是一个明确的白色光斑，不像PBR那样连续渐变 轮廓描边：水面与地面接触处有清晰的边界线 泡沫效果：岸边、礁石周围有白色泡沫纹理 如果只用普通的Phong着色或PBR来渲染水面，无论怎么调参数，都得不到这种扁平、利落的卡通感。原因在于： 真实感渲染追求连续性，卡通渲染追求离散性。 Phong光照模型中，漫反射值是一个从0到1的连续浮点数。而卡通渲染需要把这个连续值”量化”成若干个离散色阶——这就是所谓的”色阶量化”（Toon Shading / Cel Shading）。 工业界实际使用的技术栈在真实的...
