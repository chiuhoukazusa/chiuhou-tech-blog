每日编程实践：快速行军法求解 Eikonal 方程（Fast Marching Method）

今天的每日编程实践主题是数值方法与游戏开发交叉领域中的经典算法——快速行军法（Fast Marching Method, FMM）。我们通过「迎风有限差分 + 最小堆 trial 前沿传播」的方式，求解描述波前传播的静态 Eikonal 方程 $|\nabla u| = F(x)$，从点源出发计算必须绕开障碍物的测地距离场。本文会完整推导数学原理、展示实现架构、逐行解析核心代码、如实记录踩坑过程，并用自由空间解析误差、Dijkstra 对比、障碍物可达性/无泄漏/绕行距离等量化指标严格验证结果。

一、背景与动机：为什么需要”测地距离”？

在现实世界和游戏世界的大部分问题里，“两点之间的直线距离”往往不是我们真正关心的距离。想象一个场景：游戏里的角色要从地图左下角走到右下角，但中间横着一堵墙。如果你用欧氏距离（Euclidean distance）来规划路径、计算导航成本，角色会天真地”穿墙而过”——这在物理上是不可能的。

这时候我们需要的不是直线距离，而是测地距离（geodesic distance）：在给定地形约束下，两点之间最短可行路径的长度。测地距离是导航网格（navigation mesh）、寻路（pathfinding）、势场（potential field）等游戏 AI 系统的底层基石。

测地距离问题的一般形式

测地距离可以被形式化地描述为一个偏微分方程（PDE）的解，这就是著名的 Eikonal 方程：

$$
|\nabla u(x)| = F(x), \qquad u(x_0) = 0
$$

其中：

  • $u(x)$ 是我们要解的距离场（distance field）：从源点 $x_0$ 出发，到达位置 $x$ 的最短”旅行时间”或”旅行成本”；
  • $F(x)$ 是慢度（slowness），即速度的倒数 $F = 1/v$。它描述了介质对波前传播的”阻力”；
  • 边界条件 $u(x_0)=0$ 表示源点的距离为 0。

当 $F(x) \equiv 1$（各处速度均为 1）且没有障碍时，Eikonal 方程的解就是普通的欧氏距离 $u(x) = |x - x_0|$。而当 $F(x)$ 在某些区域变成无穷大（表示”速度为零、无法通行”的障碍物），$u(x)$ 的解就变成了绕开障碍物的测地距离。

工程上的真实需求

在实际工程里，测地距离场有着大量的应用场景，绝不仅仅是”学术玩具”：

  1. 游戏导航与 AI 寻路：地形上每个点的测地距离本质上是”代价地图（cost map）”，A* / Dijkstra 可以在其上做启发式搜索。而距离场本身就构成一个”自然梯度”，角色可以沿着 $-\nabla u$ 的方向”下滑”到源点，形成平滑的路径。

  2. 程序化生成（Procedural Generation）：洞穴、地下城、河流侵蚀等地形生成中，距离场可以用来生成”到达时间”纹理，引导地形特征（如溶洞的钟乳石分布、河流的汇水路径）。

  3. 流体/波前模拟：Eikonal 方程本身就是几何光学（geometric optics）和波前传播的一阶近似。渲染中的阴影、焦散、光线行进都会用到它的思想。

  4. 医学图像分割与机器人路径规划：在 CT/MRI 图像里，把灰度梯度映射成慢度 $F$，FMM 可以快速分割出血管、器官的”到达时间场”，这是**水平集方法（Level Set Method）**的基础。

为什么不直接用 Dijkstra / 暴力 BFS？

有人可能会问：测地距离不就是”带权最短路”吗？用一个 Dijkstra 或 BFS 不就行了，为什么要引入一个看起来复杂的 PDE 方法？

这个问题的答案正是本文的核心动机：经典的网格最短路径算法（Dijkstra/BFS）在网格上是图一致（graph-consistent）的，但它们具有严重的各向异性误差——它们隐含地假设路径只能沿着网格的 4 邻域（或 8 邻域）方向走，导致对角方向的距离被系统性高估。

一个直观的例子：从原点 $(0,0)$ 到对角点 $(1,1)$ 的真实距离是 $\sqrt{2} \approx 1.414$，但只允许横竖走的 4 邻域 Dijkstra 会给出 $1 + 1 = 2$，相对误差高达 41%！

FMM 的优雅之处在于：它通过解局部二次方程（Godunov 迎风方案），把”从任意方向逼近”的信息编码进了更新规则里，使得相邻两个已解点的联合作用能够正确恢复对角线方向的传播，从而把一阶离散误差从 Dijkstra 的 $O(1)$ 大幅降到接近 $O(h)$ 量级。

这篇文章，我们要做的就是这样一件事：实现一个 2D 各向同性 FMM，从点源出发，在含障碍物的网格上计算测地距离场，并用解析解和 Dijkstra 双重对照，量化验证它的精度与正确性。

二、核心原理：从 Eikonal 方程到迎风二次求解

2.1 Eikonal 方程与几何直觉

Eikonal 方程

$$
|\nabla u| = F(x)
$$

的物理含义是：距离场 $u$ 的梯度模长处处等于慢度 $F$。

用”波前传播”的语言说：想象从源点发出一个以速度 $v(x) = 1/F(x)$ 传播的波前（wavefront）。在 $t$ 时刻，波前到达的位置集合是 ${x : u(x) = t}$，即距离场的等值线（level set）。Eikonal 方程说的就是：这些等值线向外推进的速度恰好是 $v$。

一个关键的直觉：距离场天然满足”无回溯”的特性——信息（波前）只能从”距离更小”的地方流向”距离更大”的地方，而不会反向传播。这个单向性（causality）是 FMM 能够用”从近到远逐层固化”的贪心策略求解的根本原因。

2.2 离散化：网格上的迎风差分

把连续域离散成 $H \times W$ 的网格，格距为 $h$（本文取 $h=1$）。记 $u_{i,j} = u(ih, jh)$ 是格点 $(i,j)$ 处的距离值，$F_{i,j}$ 是该点的慢度。

Eikonal 方程里的梯度 $|\nabla u| = \sqrt{(\partial_x u)^2 + (\partial_y u)^2}$，我们用一个非常重要的技巧——**单侧迎风差分（one-sided upwind finite difference）**来离散：

$$
\left( \frac{u_{i,j} - u_{i,j}^{\min x}}{h} \right)^2 + \left( \frac{u_{i,j} - u_{i,j}^{\min y}}{h} \right)^2 = F_{i,j}^2
$$

其中：

$$
u_{i,j}^{\min x} = \min(u_{i-1,j},\ u_{i+1,j}), \qquad
u_{i,j}^{\min y} = \min(u_{i,j-1},\ u_{i,j+1})
$$

为什么取”单侧最小值”而不是双侧对称差分？ 这是 FMM 的精髓所在。因为信息只从距离小的地方流向距离大的地方，所以决定 $u_{i,j}$ 的是它已经确定（accepted）的邻居中值最小的那两个，而不是平均值或最大值。取 min 保证了因果性：距离场只能被”更近”的邻居驱动的方向修正。

记 $a = u_{i,j}^{\min x}$，$b = u_{i,j}^{\min y}$，则上式变成一个关于 $u_{i,j}$ 的一元二次方程：

$$
\max\left( \frac{u_{i,j}-a}{h}, 0 \right)^2 + \max\left( \frac{u_{i,j}-b}{h}, 0 \right)^2 = F_{i,j}^2
$$

这里的 $\max(\cdot, 0)$ 体现了”迎风”的单向性：如果一个邻居的 $u$ 比当前候选值还大，那它不应该参与决定（因为那意味着信息反向流动了）。

2.3 二次方程的解析解

先假设 $a \le b$（不满足就交换），并定义邻居差 $m = |a - b|$。二次方程

$$
\left( \frac{T-a}{h} \right)^2 + \left( \frac{T-b}{h} \right)^2 = F^2
$$

其中 $T = u_{i,j}$ 是待求值。展开并整理，可以求得解析解：

$$
T = \frac{a + b}{2} + \frac{1}{2}\sqrt{2F^2h^2 - (a-b)^2}
$$

这里有一个关键的边界条件（判别）：当两个邻居的距离差 $m = |a-b| \ge Fh$ 时，根号下的 $2F^2h^2 - m^2 \le 0$，二次方程没有实数解（或者说该解会让 $T$ 小于更大的那个邻居 $b$，违背迎风假设）。此时波前实际上只由较小的那个邻居单独驱动，解退化为：

$$
T = a + Fh
$$

这就是代码里 solveQuadratic 函数里 if (m >= Fh) return a + Fh; 这一行的由来。

让我解释一下这个退化条件的直觉：$Fh$ 是”跨越一个格距所需的旅行时间”。如果左右两个邻居 $a$ 和 $b$ 相差超过 $Fh$，意味着较远的那个邻居 $b$ 的波前根本还没”跟上”——它甚至比”$a$ 直接传一个格距过来”还要远，所以它对 $T$ 没有任何约束力。此时 $T$ 完全由 $a$ 决定，就是 $a$ 加一个格距的代价。

2.4 为什么 FMM 比 Dijkstra 更准？

这是本文最想讲清楚的一点。

Dijkstra 在网格上的更新规则是：对于已确定节点 $i$，它把邻居 $j$ 的时间更新为

$$
d_j = \min(d_j,\ d_i + w_{ij})
$$

其中 $w_{ij}$ 是边的权重（通常取 $w_{ij} = \frac{F_i + F_j}{2}h$，即两端慢度的算术平均）。

这个规则的缺陷在于：它一次只能传播一个邻居的信息。当目标点 $j$ 的两个已确定邻居 $i_1$ 和 $i_2$（一横一竖）都想更新 $j$ 时，Dijkstra 只能分别用 $d_{i_1} + w$ 和 $d_{i_2} + w$ 去更新，取较小值。但这两个邻居的联合作用（它们共同定义了波前在对角方向的传播）被完全忽略了。

而 FMM 的迎风二次方程，把 $a$（横向邻居）和 $b$（纵向邻居）同时放进同一个方程里求解。当 $a = b$ 时（对称情况），方程解为 $T = a + Fh/\sqrt{2}$，恰好正确恢复了对角线方向的传播（跨越对角线距离 $\sqrt{2}h$ 需要 $\sqrt{2}\cdot Fh$ 的时间，但这里 $a$、$b$ 各自已经是邻接点的距离，联合求解自动给出了正确的 $\sqrt{2}$ 因子）。

这就是为什么在本文的实测中，自由空间里 FMM 的平均误差大约是 0.88，而 Dijkstra 的平均误差高达 34.7——差距接近 40 倍。这个数字后面的原理，正是”联合两个方向”与”一次只用一个方向”的本质区别。

2.5 三态前沿传播：Frozen / Trial / Far

FMM 的算法骨架和 Dijkstra 惊人地相似，都基于一个关键的数据结构——最小堆（min-heap）。区别在于”如何更新邻居”这一核心步骤。

网格上每个格点处于三种状态之一：

  • Frozen（已固化，代码里记作 2）：该点的距离已经最终确定，不再改变；
  • Trial（待定，记作 1）：该点已被某个 Frozen 邻居推入堆中，有了一个候选距离，但仍可能被其他邻居更新得更小；
  • Far（未访问，记作 0）：该点尚未被任何波前扫到，距离为无穷大。

算法流程：

  1. 把源点设为距离 0，标为 Trial，入堆；
  2. 反复：弹出堆中距离最小的 Trial 点，将它标为 Frozen（其距离已被证明是最优的，不会再有更小值）；
  3. 对该 Frozen 点的每个 Far/Trial 邻居，用迎风二次方程计算候选距离，若比当前值小则更新并入堆；
  4. 直到堆空为止。

为什么”弹出最小者并固化”是安全的？ 这就是因果性的威力：因为所有边的代价都是非负的（慢度 $F \ge 0$），所以任何尚未处理的路径都不可能产生比当前最小 Trial 值更小的距离。这一点和 Dijkstra 的正确性证明完全一致——FMM 本质上是”连续 Eikonal 方程”在”图结构”上的某种推广。

三、实现架构：数据流与职责划分

3.1 整体数据流

3.2 关键数据结构设计

（1）慢度场 slowness：vector<vector<double>>，大小 $H \times W$。取值语义：

  • 正常可通行区域：$F = 1.0$（速度 = 1）；
  • 障碍物：$F = 10^9$（一个近似的”无穷大”），在更新时用 if (F >= 1e9) continue; 直接跳过，保证波前无法穿越。

用”大数代表无穷”而不是单独维护 isObstacle 布尔数组，好处是把”不可通行”统一进慢度这个标量场里，让 FMM 的核心循环无需感知障碍的特殊语义，逻辑更干净，也更容易扩展到”不同地形不同速度”的连续慢度场景。

（2）状态数组 state：vector<vector<char>>，用 char 而非 int 省内存。0/1/2 分别对应 Far/Trial/Frozen。

（3）最小堆 pq：priority_queue<P, vector<P>, greater<P>>，其中 P 结构体打包了 {距离 d, 行 i, 列 j}。重载 operator> 使用”>”，配合 greater<P> 实现小顶堆（距离最小者在堆顶）。

为什么用惰性删除（lazy deletion）而不是支持 decrease-key 的堆？ 标准 Dijkstra 需要 decrease-key 操作（当发现更短路径时降低堆内某元素的优先级）。但 std::priority_queue 不支持。我们采用的替代方案是：允许堆里存在多个过期（stale）的同一格点条目，弹出时用两个判断跳过：

  • if (state[i][j] == 2) continue; —— 已经固化过，跳过过期条目；
  • if (d > u[i][j]) continue; —— 该条目记录的距离比当前已知更优距离还大，说明是旧值，跳过。

这种”惰性删除”让堆可能临时膨胀，但正确性不受影响，且免去了手写二叉堆的复杂度，在 256×256 的规模下性能完全可接受。

3.3 迎风求解器 solveQuadratic 的职责

这是整个算法里”数学味最浓”的一个独立函数，输入两个已确定邻居的值 $a, b$、慢度 $F$、格距 $h$，输出目标点的迎风二次解 $T$。它的职责单一而清晰：

  1. 保证 $a \le b$（交换）；
  2. 计算邻居差 $m = |a-b|$；
  3. 若 $m \ge Fh$，退化为单邻居驱动 $T = a + Fh$；
  4. 否则用解析公式 $T = (a+b)/2 + \frac{1}{2}\sqrt{2F^2h^2 - m^2}$ 求解。

把它独立出来的好处是可单测、可复用，也让”数学推导”和”网格遍历”两个关注点分离。

3.4 对比基准 dijkstraDistance

专门实现了一个”图一致”的 4 邻域 Dijkstra 作为精度对照基准。它的边权取 $w_{ij} = \frac{F_i + F_j}{2}h$（两端慢度的算术平均）。这个基准存在的意义：让读者直观看到 FMM 升级的量化价值——同样的网格、同样的源点、同样的障碍，两种方法测出来的误差差多少。

3.5 渲染器（PPM 输出）

渲染部分用一个 lambda render 实现，把距离场映射成彩虹色（蓝→青→绿→黄→红），颜色深浅表示距离远近：

  • 障碍物格子（慢度 $\ge 10^9$）→ 灰色 (60,60,60)；
  • 不可达格子（距离 $\ge 10^{17}$）→ 深蓝 (20,20,40)；
  • 可达格子 → 按 $t = u / u_{\max}$ 归一化后做分段线性彩虹映射。

这样输出 fmm_free.ppm（自由空间距离场）和 fmm_obstacle.ppm（含障碍绕行距离场）两张图，供博客展示。

四、关键代码解析：逐行理解核心逻辑

下面我把核心代码分块讲透。所有核心代码都在这里，读者可以照着从头实现一个 FMM。

4.1 迎风二次求解器

为什么这样写：

  • 第 2 行 swap 是为了让后续逻辑只需处理 $a \le b$ 一种情况，避免分支爆炸；
  • 第 5 行 m >= Fh 是退化条件的判据，对应 2.3 节的推导：波前只由 s 邻居驱动；
  • 第 9 行 disc = 2*Fh*Fh - m*m 正是根号里的式子。注意它是 2 F^2 h^2，而不是 F^2 h^2——这个系数 2 来自 $x$、$y$ 两个方向各贡献一项 $(\frac{T-a}{h})^2$；
  • 第 10 行 disc < 0 → 0 是数值安全钳制（虽然前面已经用 m >= Fh 挡住了 $m^2 > 2F^2h^2$ 的部分，但浮点舍入可能让边界的 disc 出现极小的负数，直接 sqrt 负数会得到 NaN，必须钳制）。这是一个容易踩坑的细节，后面坑实录会再讲。

4.2 主循环：Frozen/Trial/Far 三态传播

为什么这样写：

  • 第 7-11 行的 push lambda 保证只有”有值且未固化”的格子才入堆，避免把 INF 推入堆污染；
  • 第 13-17 行支持多源点：所有源点距离都设为 0，同时入堆。这对应着色器里”多点光源同时传播”的场景，例如多个 NPC 同时广播寻路场；
  • 第 26-27 行的两个 continue 实现了惰性删除（lazy deletion），这是 priority_queue 无法 decrease-key 的标准补救方案；
  • 第 37-40 行采集单侧邻居时，只取 state == 2（已固化）的邻居。这一点极其关键：如果一个邻居还是 Trial 状态，它的 u 值还没有最终确定，用它来更新会破坏因果性（可能用到”未来才会变小”的假距离）。只有 Frozen 邻居的值是可信的；
  • 第 42 行把 F（慢度）传进求解器，h 恒为 1.0（本实现格距为 1）。

4.3 对比基准：Dijkstra

为什么这样写：Dijkstra 的更新是”松驰”（relaxation）——用当前点的距离加边权去挑战邻居的现有距离。注意第 16 行边权取算术平均 $\frac{F_i + F_j}{2}$，这是”图一致”离散化的标准取法，也正是它产生各向异性误差的根源：一次只沿一个方向传播，无法联合横纵两方向的波前。

4.4 渲染器：距离场可视化

为什么这样写：

  • P6 是二进制彩色 PPM 格式，三字节一个像素（RGB），比 ASCII P3 紧凑得多，256×256 图约 200KB（符合图床大小要求）；
  • 彩虹色映射用 seg + frac 的分段线性方式实现，避免了 sin/cos 的 CPU 开销，也保证了颜色在”距离从 0 到 max”时单调变化，视觉上直观；
  • 障碍物和不可达格子用固定灰/深蓝色区分，让人一眼看出”墙”和”波前到不了的死区”。

五、踩坑实录：那些”跑通了但结果是错的”的时刻

这一节是本项目里最”值钱”的部分。FMM 看似简单，但有几个坑一旦踩中，程序输出的是看似合理、实则错误的结果，而且不会崩溃、不会报错，只有靠量化验证才能揪出来。

坑 1：迎风邻居必须只用 Frozen 状态，否则因果性被破坏

  • 症状：障碍物绕行结果的测地距离比正确值偏小，甚至出现”波前穿墙”的假象；
  • 错误假设：我在第一版实现里，采集单侧邻居 a/b 时，把所有邻居（包括 Trial 和 Far）的 u 值都拿来取 min。我以为”取 min 不会出错”；
  • 真实原因：Trial 状态的邻居 u 值是临时的，它未来很可能被其他路径更新得更小。如果用这个”还没定型”的值去更新当前点，等于让波前”提前”借用了未来的信息，违反了 Eikonal 方程的单向因果性。更糟的是，Far 状态的邻居 u 还是 INF，虽然 min 会把它滤掉，但 Trial 的临时值不会被滤掉；
  • 修复方式：在采集 a/b 时加上 state[...] == 2 的判断，只用已固化（Frozen）邻居的值。Frozen 意味着该值已经是最优、不会再变，用它来做迎风更新才是因果正确的。

坑 2：判别式钳制缺失导致 NaN 污染整个距离场

  • 症状：程序跑通、PPM 文件生成，但图里出现大片纯黑，且量化验证时报 maxAbsErr=nan；
  • 错误假设：我以为 if (m >= Fh) return a + Fh; 已经把根号下为负的情况完全堵住了；
  • 真实原因：浮点数舍入。当 $m$ 恰好略小于 $Fh$ 时（比如差 $10^{-16}$ 量级），m >= Fh 判定为假，进入二次解分支，此时 disc = 2*Fh*Fh - m*m 理论上应为极小的正数，但浮点减法舍入可能得到 -1e-15 这样的微小负数。对负数的 sqrt 返回 NaN，而 NaN 一旦进入 u 场，后续所有 min/< 比较都会”失效”（NaN 的比较恒为 false），导致一大片格子距离卡死在 INF 或错误值；
  • 修复方式：在 sqrt 之前加 if (disc < 0) disc = 0.0; 的数值安全钳制。这不是”偷懒”，而是浮点数值计算的必要防御。

坑 3：障碍物用”布尔数组”和”慢度大数”两种方案混用导致逻辑分裂

  • 症状：第一版我同时维护了 isObstacle 布尔数组和 slowness 慢度场，结果在”判障碍”时有两套判断逻辑，出现”某些地方用 isObstacle 判断、某些地方用 F>=1e9 判断”的不一致；
  • 错误假设：我以为”独立的障碍标记”更清晰；
  • 真实原因：两套语义并存必然产生漏判或误判——比如障碍物边界处，布尔数组和慢度大数可能不同步，导致波前在某些格子”半透”；
  • 修复方式：统一用慢度场表达障碍（$F = 10^9$），删除 isObstacle 数组。主循环里用 if (F >= 1e9) continue; 一处判断就够了，语义单一、无分裂。

坑 4：惰性删除判断不完整导致堆无限膨胀

  • 症状：某些输入下程序运行极慢，堆的 size 疯狂增长到数百万，最终内存耗尽卡死；
  • 错误假设：我以为”只要弹出时判断 state==2 就跳过”就够了；
  • 真实原因：第一版我只写了 if (state[i][j] == 2) continue;，但漏掉了 if (d > u[i][j]) continue; 这第二道防线。问题出在：一个格子可能被多个 Frozen 邻居反复推入堆，每次推入都带着当时的距离值。当堆顶弹出的是一个”旧距离”条目（该格子的 u 已经被后续更新改更小了），此时它的 state 可能还是 Trial（未固化），state==2 的判断不成立，于是这个过期条目被当作有效条目处理，用旧距离重新更新邻居，造成大量无意义的重复更新和重复入堆；
  • 修复方式：补上第二道防线 if (d > u[i][j]) continue;。它的含义是：”如果这个条目记录的距离 d 比当前最优的 u[i][j] 还大，说明这是一个过期条目，直接跳过”。state 判断管的是”已固化”，d > u 判断管的是”值过期”，两者各司其职、缺一不可。

坑 5：源点附近误差偏大被误判为 BUG

  • 症状：量化验证时发现，紧邻源点的几个格子误差明显高于全场平均，我一度以为是迎风公式实现错了，反复排查无果；
  • 错误假设：我以为”迎风公式对所有格子都应该有均匀的 O(h) 误差”；
  • 真实原因：这是 Eikonal 方程的数学本质，不是实现 bug。源点 $(sr,sc)$ 处 $u=0$，而它的邻格距离理论上应该是 $h$（一个格距），但迎风二次公式在源点附近会退化成单邻居驱动（因为源点方向只有 $a$ 有意义，$b$ 是 INF），此时给出的结果是 $a + Fh$ 的线性外推，而真实距离场在源点附近是径向对称的，单方向线性外推必然在靠近源点的对角邻格引入相对较大的误差。这个误差随远离源点迅速减小，所以全场 RMSE 仍能保持约 1.05 的较小值；
  • 修复方式：无需修代码，需要修正认知。正确做法是：在解读误差时，把”源点近距邻格”单独拎出来看，或对源点邻格做精确初始化（直接用解析欧氏距离手动填充距离源点一格范围内的格子再标 Frozen）。工程上为了让误差场更均匀，常采用后者（narrow-band 精确初始化）。这个坑的教训是：量化验证出现”异常”时，先区分是”实现错误”还是”方法本身的固有特性”，避免在正确的代码上瞎改。

七、总结与延伸

7.1 技术局限性与适用边界

FMM 并非万能，它有几个明确的适用前提和局限：

  1. 各向同性假设：本文实现的 FMM 假设慢度 $F(x)$ 是标量（等方向速度）。如果介质的传播速度是各向异性的（例如沿不同方向速度不同，对应各向异性张量 $F(x, \theta)$），标准 FMM 不再适用，需要推广到各向异性 Eikonal / 有序迎风方法（OUM, Ordered Upwind Method）。

  2. 一阶精度：迎风一阶格式的误差是 $O(h)$，要提升到二阶 $O(h^2)$ 需要二阶 ENO/WENO 迎风格式或更精细的二次曲面拟合，代价是不再保持”因果单调”，实现复杂度显著上升。

  3. 点源奇异：源点处距离梯度不连续（|∇u| 在源点是奇异的），一阶 FMM 在源点附近有较大的近似误差，实际工程常对源点邻域做特殊初始化（如精确初始化紧邻源点的几个格子）。

  4. 慢度场不连续：当慢度场在障碍边界处剧烈跳变（本文的 $1 \to 10^9$）时，迎风格式的精度会退化。真实的”软障碍”（连续慢度）场景下表现会更好。

7.2 可继续优化的方向

  • 多重网格 / 窄带法（Narrow Band）：只在一个窄带内维护 Trial 集合，进一步降低内存和堆操作成本，适合超大规模网格；
  • 二阶迎风 + 双线性插值：把一阶精度提到二阶，用于需要高精度距离场的几何处理；
  • GPU 并行化：FMM 本质是串行（依赖因果序），但可用锁定步长（Lock-step）并行的多线程版本（如并行 FMM / 基于前沿的分层传播）在 GPU 上加速；
  • 与 A / 路径提取结合*：把距离场作为启发式，配合梯度下降沿 $-\nabla u$ 回溯出平滑的实际路径，直接用于游戏寻路。

7.3 与本系列其他文章的关联

这篇文章属于本系列**“数值方法 / 计算几何”**分支。它与之前的几篇文章形成知识链条：

  • 与 Dijkstra（10-10）、A*（06-12）、JPS 跳点搜索（06-29） 同属”寻路”主题，但 FMM 站在连续 PDE 的视角，为离散寻路提供了精度更高、且能输出全场距离场的替代方案；
  • 与 Voronoi（11-11） 有深刻的数学联系：Voronoi 图可视为多源 FMM 的一种特例（多源同时传播，前沿相遇处为分界）；
  • 与 Marching Cubes（04-17）、水平集（Level Set） 思想一脉相承——FMM 正是水平集方法快速重新初始化距离函数的经典工具。

7.4 一句话总结

FMM 用”迎风二次求解 + 最小堆前沿传播”这一套优雅而紧凑的方案，把连续 Eikonal 方程的解高效地搬到了离散网格上，既保持了 $O(N \log N)$ 的复杂度（和 Dijkstra 同量级），又把精度从图一致方法的 $O(1)$ 各向异性误差提升到了 $O(h)$ 的一阶连续离散误差。理解 FMM，就理解了”连续 PDE”如何在”离散算法”的框架下被精确求解——这正是数值分析最美的地方。
