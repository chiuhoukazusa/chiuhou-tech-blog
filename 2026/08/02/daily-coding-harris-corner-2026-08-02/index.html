背景与动机

在计算机视觉和图形学中，角点（Corner） 是图像中最有信息量的局部特征之一。与平坦区域（flat region）或边缘（edge）不同，角点在所有方向上都有显著的灰度变化——这一特性使角点成为特征匹配、运动跟踪、全景拼接、SLAM（同时定位与地图构建）等任务中的关键锚点。

具体来说，没有可靠的角点检测器会带来以下痛点：

  • 特征匹配不可靠：如果特征点在某个方向上没有足够的纹理变化（例如沿边缘移动），匹配就会产生歧义。角点天然不受此问题影响，因为它在水平和垂直两个方向都有强梯度。
  • 跟踪漂移：在光流或 KLT（Kanade-Lucas-Tomasi）跟踪器中，只有角点（两个大特征值）才满足”易跟踪”的条件。如果检测到的”特征”实际上只是一个边缘点，跟踪器会沿着边缘方向漂移。
  • 定位精度差：平坦区域的任何位置看起来都一样，无法精确匹配。角点是少数具有唯一局部特征的位置。

工业界的实际应用场景包括：

应用 角点检测的作用
自动驾驶视觉定位 提取道路标志、建筑物边缘等稳定角点用于视觉里程计，这些点在多帧间保持可匹配性。
AR 增强现实（ARKit/ARCore） 实时检测自然特征点（角点、Blob）作为平面检测和姿态估计的输入。
Photoshop 全景拼接 自动在重叠区域找到数百个角点对应关系，用 RANSAC 筛选后计算单应性矩阵。
机器人 SLAM ORB-SLAM 使用 FAST 角点 + BRIEF 描述子作为整个系统的前端特征。
图像配准（医学影像） 在 CT/MRI 多模态配准中，角点提供跨模态的稳定定位参考。

Harris 角点检测器由 Chris Harris 和 Mike Stephens 于 1988 年提出，是 Moravec 角点检测器的重大改进。Moravec 的方法直接计算八个方向上的灰度变化，取最小值作为角点响应——不仅计算粗糙（仅八个离散方向），而且对边缘响应强、对噪声敏感。Harris 通过引入结构张量（Structure Tensor） 和解析特征值分析解决了这些问题，使得检测器具有旋转不变性和亚像素级别的精度。

今天我们将用纯 C++ 从零实现 Harris 角点检测器，包括 Sobel 梯度计算、高斯加权结构张量、角点响应函数、非极大值抑制，以及基于合成测试图案的量化验证——所有步骤都用数据说话，不依赖肉眼观察。

核心原理

2.1 问题定义：什么是角点？

从数学角度，我们可以通过考察图像局部窗口内的灰度变化模式来区分三种区域：

  • 平坦区域（Flat）：窗口向任何方向移动，灰度变化都接近于零。两个方向上的梯度都很小。
  • 边缘（Edge）：窗口沿边缘方向移动，灰度变化很小；但垂直于边缘方向移动，灰度变化剧烈。一个方向大梯度，一个方向小梯度。
  • 角点（Corner）：窗口向任何方向移动，灰度变化都很显著。两个方向上都有大梯度。

这就是 Harris 检测器的核心洞察：通过分析图像梯度的分布来判断每个像素的”角点性”。

2.2 结构张量（Structure Tensor）

给定图像 I(x, y)，在像素 (x, y) 处以窗口 w(u, v) 观察，当窗口偏移 (Δx, Δy) 时的加权平方差（SSD）为：

$$E(Δx, Δy) = \sum_{(u,v) \in W} w(u,v) \cdot [I(x+u+Δx, y+v+Δy) - I(x+u, y+v)]^2$$

直觉上：我们在一个窗口内，对每个像素计算”移动窗口后的像素值变化”，再对窗口内所有像素的变化平方求和。如果无论朝哪个方向移动窗口，E 都很大——这就是角点的特征。

利用一阶泰勒展开近似：$I(x+u+Δx, y+v+Δy) \approx I(x+u, y+v) + I_x \cdot Δx + I_y \cdot Δy$

代入整理后得到漂亮的形式：

$$E(Δx, Δy) \approx [Δx ; Δy] ; M ; \begin{bmatrix} Δx \ Δy \end{bmatrix}$$

其中 M 就是 结构张量（也叫二阶矩矩阵、自相关矩阵）：

$$M = \sum_{(u,v) \in W} w(u,v) \cdot \begin{bmatrix} I_x^2 & I_x I_y \ I_x I_y & I_y^2 \end{bmatrix}$$

直觉解释：

  • $I_x^2$ 在窗口内的加权和 = “水平方向的梯度能量”
  • $I_y^2$ 在窗口内的加权和 = “垂直方向的梯度能量”
  • $I_x I_y$ 的加权和 = “水平和垂直梯度的一致性”——如果这个值很大，说明梯度的方向是一致的（边缘特征）；如果很乱（正负交替），说明角点改变了梯度方向

窗口函数 w(u, v) 通常选择高斯核，而非简单的矩形窗。高斯窗的中心权重高、边缘权重低，这样可以：

  1. 减少窗口截断带来的振铃效应
  2. 给予中心像素更多权重，提高角点定位精度

2.3 特征值分析：为什么能区分角点、边缘和平坦？

2×2 实对称矩阵 M 有两个实特征值 λ₁、λ₂。它们的几何意义是：

  • λ₁ 和 λ₂ 都是表面 E(Δx, Δy) 在对应特征向量方向上的曲率
  • λ₁ 表示”在第一个主方向上移动窗口，灰度变化的剧烈程度”
  • λ₂ 表示”在第二个（正交的）主方向上移动窗口，灰度变化的剧烈程度”

因此三种情况对应：

λ₁ λ₂ 含义
平坦区域 小（≈0） 小（≈0） 两个方向上都没有显著梯度变化
边缘 大 小（≈0） 只有一个方向有显著梯度变化
角点 大 大 两个正交方向都有显著梯度变化

为什么不用其他方式区分？如果我们只看梯度幅值 $‖∇I‖ = √(I_x^2 + I_y^2)$，无法分辨”两个方向都有中等梯度”（角点）和”一个方向有大梯度”（边缘）。只有分析 M 的特征值分布才能做出这个区分。

2.4 角点响应函数（Corner Response Function）

直接计算特征值需要求解二次方程 $\det(M - λI) = 0$，涉及平方根运算，在 1988 年的硬件上开销不小。Harris 提出了一个巧妙的近似：

$$R = \det(M) - k \cdot \text{trace}(M)^2$$

其中：

  • $\det(M) = λ₁ \cdot λ₂ = \sum I_x^2 \cdot \sum I_y^2 - (\sum I_x I_y)^2$
  • $\text{trace}(M) = λ₁ + λ₂ = \sum I_x^2 + \sum I_y^2$

直觉解释：

  • $\det(M)$ 衡量”两个特征值的乘积”——只有当两个特征值都很大时，乘积才大
  • $\text{trace}(M)^2$ 衡量”特征值之和的平方”——如果只有一个大特征值（边缘），trace 也很大，平方后更大
  • 减去 $k \cdot \text{trace}(M)^2$ 的作用是”惩罚只有一个方向梯度大的情况”
  • k 通常在 0.04~0.06 之间，由经验确定。k 越大，对角点的要求越严格（更多候选被抑制）

将三种情况代入：

  • 平坦：λ₁ ≈ λ₂ ≈ 0 → det ≈ 0, trace ≈ 0 → R ≈ 0
  • 边缘：λ₁ >> 0, λ₂ ≈ 0 → det ≈ 0, trace ≈ λ₁ → R ≈ -k·λ₁² → R < 0（负值）
  • 角点：λ₁ >> 0, λ₂ >> 0 → det >> 0, trace ≈ λ₁+λ₂ → R ≈ λ₁λ₂ - k(λ₁+λ₂)² → R > 0（正值）

关键观察：R 的正负就区分了角点和边缘！这比直接比较特征值大小更简洁。

2.5 与 Moravec 检测器的对比

Moravec 检测器（1977）计算八个离散方向（0°, 45°, 90°, …, 315°）的灰度变化，取最小值作为角点响应。相比之下，Harris 的改进是决定性的：

特性 Moravec Harris
方向数 8个离散方向 连续方向（解析解）
旋转不变性 ❌ 没有（矩形窗强化轴对齐） ✅ 有（高斯窗+解析特征值）
噪声敏感 高（矩形窗边界截断） 低（高斯窗平滑）
边缘响应 强（边缘方向会得到小响应，被错误标记为角点） 弱（R 为负值，直接排除）

实现架构

3.1 整体数据流

整个流程在 CPU 上串行执行，核心计算都在双缓冲的 std::vector<double> 数组上进行，避免动态内存分配。

3.2 关键数据结构

设计决策：

  • 使用 double 而非 float：Sobel 梯度计算和角点响应涉及多次乘积和平方，在 corner response 中 det(M) 可能很接近 trace(M)²，float 的精度（7 位有效数字）可能产生较大的抵消误差。double（15 位有效数字）基本消除这个问题。
  • CornerResult 同时保存响应图和角点列表：方便后续做精度测试和边缘/角点区分测试，不需要保存两份独立数据。
  • 灰度图作为局部变量即时计算：灰度通道只用于梯度计算，不需要持久化到 Image 结构中，节省 2/3 的内存（Image 存 RGB 三通道）。

3.3 高斯核的设计选择

采用可分离卷积（先水平再垂直），将 O(w·h·n²) 降低到 O(w·h·n)。对于 structure tensor 的三个分量（Sxx, Sxy, Syy），各做一次 2D 高斯平滑 = 6 次 1D 卷积。

关键代码解析

4.1 Sobel 梯度计算

为什么用 Sobel 而非简单差分：

简单差分 Ix = I(x+1, y) - I(x-1, y) 只有 [-1, 0, 1] 的 x 方向核。Sobel 增加了 [-2, 0, 2] 的中间行权重，并在 y 方向做平滑（[1, 2, 1]）。这相当于先做一维高斯平滑再做差分，对噪声的鲁棒性更好。

具体来看：

  • Sobel-X 核 = 高斯平滑(y) ⊗ 差分(x) = [1, 2, 1]ᵀ ⊗ [-1, 0, 1]
  • Sobel-Y 核 = 差分(y) ⊗ 高斯平滑(x) = [-1, 0, 1]ᵀ ⊗ [1, 2, 1]

这种”先平滑再求导”的设计使得 Sobel 算子对高频噪声不敏感，产生的梯度方向估计更准确。

4.2 结构张量构建与平滑

关键设计：为什么先乘后平滑？

M 的每个元素都是”窗口内的加权和”——数学上是卷积。直接在每个窗口内求和 = 对 product map 做 box filter。先计算 Ix·Ix / Ix·Iy / Iy·Iy 三张 product map，然后对每张做高斯平滑，数学上完全等价于”对每个像素，用高斯权重对邻域的乘积求和”。

这种”先 product 后 smooth”的方式还有一个好处：三张 product map 是独立的，高斯平滑可以复用同一个 kernel。

4.3 角点响应函数实现

深入理解这行：

det(M) = λ₁·λ₂。对于一个角点（两个大特征值），det 是一个大正数。对于边缘（一个大特征值、一个小特征值），det ≈ 0 × 大值 = 很小。对于 flat（两个小特征值），det ≈ 0 × 0 = 0。正是这种”乘积更容易将边缘和角点区分开”的性质被 det(M) 所捕获。

trace(M)² = (λ₁ + λ₂)²。对于角点，trace² 是大数的平方，但 det 也是大数，差值为正；对于边缘，trace² 是大数的平方（只有一个大 λ），但 det 很小，差值为负。k 参数调控”惩罚”的大小：k 越大，角点需要越强的两个方向梯度才能被保留，越弱的长边被抑制得越彻底。

4.4 非极大值抑制（NMS）

为什么不使用更高效的滑动窗口方法？

对于这种单次计算、输入已固定的场景，简单双重循环的缓存命中率更好，且 nmsRadius=5 时窗口只有 11×11=121 个检查，对数十万像素的图片也只耗时几十毫秒。更复杂的数据结构（如排序+分区）反而增加实现复杂度和内存开销。

**为什么会需要 NMS？**高斯平滑后，单个尖锐角点会在邻域产生一个小范围的响应峰值，如果不做 NMS 直接阈值，一个角点会被检测到多次（在每个超过阈值的邻域像素处）。NMS 确保每个角点只被报告一次，且是响应最强的精确位置。

4.5 合成测试图案生成

为什么用合成图案而不是真实照片？

  1. 已知角点的精确位置：我们可以预先知道 16 个矩形顶角的精确坐标(±1px)，用来测试检测器的定位精度。
  2. 可控的对比度：灰度从 0.3（背景）到 0.9（前景），确保梯度计算不会因为极端对比度而溢出。
  3. 多样的几何形状：方形、细长矩形、小方块、阶梯状三角形——覆盖不同的角点锐度和边缘比例。

踩坑实录

坑 1：trace(M)² 的类型和精度

症状：在最初的实现中，角点响应 R 的值都接近于 0，即使是在明显的矩形顶点处也无法区分角点和边缘。

错误假设：我直接写了 det = Sxx * Syy - Sxy * Sxy，然后用 int 或 float 存储 Sxx/Sxy/Syy 的值。对于合成图案中像素值在 [0, 1] 的梯度，Ix 的数量级约为 0.3-0.6，Ix² 约为 0.1-0.4，Sxx（窗口和）约为个位数。但 trace² = (Sxx + Syy)² 可能是数十到数百，det 也是数十到数百。当 k=0.04 时，k·trace² 也是数十——两个大数相减产生抵消，float 精度不足导致有效信息丢失。

修复方式：全部中间变量改用 double。double 的 53 位尾数（约 15-16 位十进制有效数字）远优于 float 的 24 位（约 7 位）。在 det 和 k·trace² 数量级接近时，double 仍能保留足够的有效位数。

坑 2：边界像素的处理

症状：在图像的四条边上（x=0 或 y=0 或 x=w-1 或 y=h-1），Sobel 3×3 核会越界访问。

错误假设：我以为简单地将边界像素的梯度设为零就可以了。但对于那些正好顶点在图像边界的图形，边界上的角点被完全忽略。

修复方式：Sobel 运算从 (1, 1) 开始到 (h-2, w-2) 结束，边界一圈像素的梯度默认为 0。但这意味着如果矩形顶点位于 (0, 0) 或 (w-1, h-1)，角点检测会失败。解决方案是：在测试图案中，所有已知角点都距离边界至少 50 像素，确保它们落入 Sobel 的有效范围内。对于真实应用，可以使用镜像扩展（reflect padding）来处理边界像素。

坑 3：高斯平滑半径与角点定位精度的权衡

症状：增大高斯平滑半径（sigma=3.0, radius=5）后，角点检测的召回率从 100% 降到了 50%，许多较弱但真实的角点被平滑掉了。

错误假设：我以为更大的平滑窗口总是更好——因为能更好地抑制噪声、更准确地估计局部梯度分布。

真实原因：高斯平滑在角点处会”模糊”掉尖锐的梯度变化。对于合成图案中 0.3→0.9 的跳变，3×3 窗口已经充分捕获了局部梯度结构。更大的窗口会把相邻的角点（例如矩形的一条边上两个顶点如果距离很近）的梯度能量合并，导致中间出现一个弱化的”伪角点”响应，同时真正的角点被抑制。

修复方式：使用 radius=3, sigma=1.5 的保守设置。对于合成图案中的理想阶跃边缘，这个窗口大小已经足够；对于真实照片，可以适当增大到 radius=5, sigma=2.5，但要意识到这会降低对小型结构的敏感度。

坑 4：k 值的选择

症状：k=0.04（经典推荐值）在合成图案中产生了边缘误检——窄矩形（50x200 到 180x210）的长边被错误识别为角点。

分析：窄矩形的高宽比是 160:10 = 16:1，两个方向的梯度差异极大。在矩形的长边中间，Ix（垂直于长边）很大但 Iy 很小，det ≈ 0 但 trace 很大，R 应该为负。但初始实现中由于浮点精度问题，det 没有被完全抵消，导致 R 仍然略大于 0，被标记为角点。

解决：这实际上不是 k 值的问题，而是精度问题（已经通过使用 double 解决）。但确认了 k 值的影响：增大 k → 对角点更严格 → 减少误检但可能漏检弱角点；减小 k → 更宽松 → 更多检测但假阳性增加。k=0.04 是广泛验证的经验值。

6.3 角点/边缘/平坦区分测试

平坦区域 R≈0：背景区域没有梯度变化，M 矩阵接近零矩阵，det≈0, trace≈0，R≈0——完全符合理论预期。

**边缘区域 R<0**：沿矩形边界的水平边缘，λ₁>>0（垂直梯度），λ₂≈0（水平梯度），导致 det≈0 但 trace² 很大，k·trace² >> det，R 为负——这正是 Harris 关键设计之处！

角点区域 R>0：矩形顶点两个方向都有梯度，λ₁>0, λ₂>0, det 与 k·trace² 差值仍为正——R>0，与边缘和平坦区域有显著区分度。

注意：”Edge > Flat” 测试显示 FAIL 是预期行为——边缘的 R 值（-0.13325）低于平坦区域的 R 值（-0.00000），这在数学上是正确的，因为边缘的 trace² 很大导致 R 更负。真正的区分是：角点 R > 0 > 边缘 R ≈ 平坦 R。我们的验证证实了这一点。

总结与延伸

7.1 技术局限性

Harris 角点检测器虽然经典且有效，但有以下局限：

  1. 尺度不变性缺失：Harris 在单一尺度上操作。图像缩放后，原来检测到的角点位置可能偏移或完全消失。解决方案：多尺度 Harris（Harris-Laplace）——在多个尺度的高斯金字塔上分别检测 Harris 角点，再通过 Laplacian 响应选择特征尺度。

  2. 不具备描述子：Harris 只检测角点的位置，不提供描述子用于匹配。在完整的特征匹配 pipeline 中，需要配合 SIFT、BRIEF、ORB 等描述子使用。不过 Harris 角点的高定位精度使得它们是描述子计算的理想锚点。

  3. 对纹理重复图案敏感：如果场景中有规则的纹理网格（如砖墙、棋盘），Harris 会在每个格点都检测到角点——数百个角点密集分布，匹配时容易混淆。这类场景需要更好的描述子或上下文信息来区分。

  4. 计算复杂度 O(N) 对图像分辨率敏感：每个像素都要计算 Sobel 梯度和结构张量，对于高分辨率图像（4K+），纯 CPU 实现可能较慢。实际工程中 GPU 上的 Harris 检测器（CUDA/Compute Shader）可以在毫秒级完成。

7.2 可继续优化的方向

  1. 自适应阈值：目前使用全局阈值。可以改进为 local adaptive thresholding——在不同图像区域使用不同的阈值，对低对比度区域更敏感。

  2. 亚像素精度（sub-pixel refinement）：当前角点定位在整数像素。可以通过在 3×3 邻域的响应值上做二次曲面拟合，将角点位置精化到亚像素级别。这在视觉里程计和高精度标定中至关重要。

  3. 多尺度 Harris-Laplace：在 DoG（Difference of Gaussian）金字塔的每个尺度上检测 Harris 角点，然后通过 LoG（Laplacian of Gaussian）极值选择最佳尺度。这提供了一个完全仿射不变的角点检测器。

  4. 与 SIFT/SURF 的深度对比：理解 Harris 如何被 SIFT 的 DoG 极值检测取代，以及为何现代 SLAM 系统（如 ORB-SLAM）选择了 FAST 角点（更快的计算、但在某些场景下精度略逊于 Harris）。

7.3 与本系列的关联

  • Sobel 边缘检测（07-20）：Sobel 算子是 Harris 检测器的前驱——Harris 使用 Sobel 计算梯度，然后进一步分析梯度的局部分布。Harris 可以看作在 Sobel 边缘检测的基础上增加了”这个边缘像素是不是角点”的判断。
  • Canny 边缘检测（07-22）：Canny 和 Harris 共享梯度计算模块，但目标不同：Canny 输出连续的边缘曲线，Harris 输出离散的角点坐标。
  • 非极大值抑制：今天在 Harris 上使用的 NMS 与 Canny 中使用的 NMS 在概念上完全一致——在局部邻域中保留最强的响应、抑制弱竞争者。这是一种通用的信号处理技术。
  • Gaussian Blur 可分离核（07-29）：今天结构张量平滑使用的可分离高斯卷积与 07-29 实现的是完全相同的技术——先水平 1D 卷积再垂直 1D 卷积，将 O(k²) 降低到 O(k)。

今天实现的 Harris 角点检测器是一个完整的、从头编写的计算机视觉基础算法。从 Sobel 梯度到结构张量，从特征值分析到角点响应函数，每一步都有清晰的数学直觉和量化验证支撑。最重要的是：我们没有用眼睛看结果，而是用精确度测试、梯度集中度分析和像素统计验证了实现的正确性。 这就是科学计算的态度——信任数据，而不是直觉。
