每日编程实践: Bresenham 圆与椭圆光栅化算法

背景与动机

在计算机图形学的世界里，圆和椭圆是最基础的几何图元之一。从 UI 按钮的圆角矩形到游戏小地图的视野范围圈，从数据可视化中的饼图到 CAD 软件的工程绘图——曲线图元的绘制无处不在。

然而，我们面对的显示器是由离散的像素网格组成的。如何用离散的像素点去最佳逼近一个连续的光滑曲线？这就是光栅化算法的核心问题。

最朴素的想法是遍历每个像素，判断它是否在圆上——但这意味着我们必须计算每个像素到圆心的距离并做浮点比较，对于一个 800×600 的图像，光是画一个半径为 200 的圆就要做 48 万次浮点运算。在早期的计算机上，这种开销是不可接受的。

Bresenham 圆形算法由 Jack Bresenham 在 1977 年提出，与他的直线算法一样，核心思想是用纯整数运算逐步决定下一个像素的位置，完全避免浮点运算和乘法。这种优雅的增量算法至今仍是 GDI（Windows 图形设备接口）和 X11 等底层图形系统中圆和椭圆绘制的标准实现。

更进一步，椭圆比圆多了一个维度：它有两个不同的半轴。Bresenham 椭圆算法（也称为 Midpoint Ellipse Algorithm）将椭圆的绘制分成两个区域——x 占主导的区域和 y 占主导的区域——分别处理，也是纯整数运算。

本文将完整实现这两个算法，并使用量化验证来确保正确性：对称性测试、径向误差分析、像素计数验证——每一组数据都告诉我算法的实际表现，而不是靠眼睛来判断图画得对不对。

在工业界，Bresenham 系列算法虽然古老，但仍广泛应用：

  • 嵌入式系统 / 无 GPU 环境：单片机显示屏、LCD 面板、电子纸
  • CAD 软件的光标绘制：需要精确的像素级控制
  • 字体渲染：TrueType 字体中的椭圆弧形
  • 教育用途：理解光栅化的最基础原理，通往 GPU 光栅化管线的第一步

没有这个算法，每一个圆和椭圆都需要昂贵的逐像素计算，在早期硬件上根本无法实时渲染。

核心原理

圆的隐式方程与决策参数

圆的隐式方程为：

对于圆上的点，f = 0；圆内点 f < 0；圆外点 f > 0。

Bresenham 圆形算法的核心洞察是：利用 8 路对称性。如果我们计算出圆在第一八分圆（从 (0, r) 到 (r/√2, r/√2)）上的所有像素点，就可以通过对称操作得到整个圆：

这就是为什么算法只遍历 x = 0 到 x = y 的部分——只需要八分之一的计算量。

在第一八分圆中，x 从 0 开始递增，y 从 r 开始递减。每一步我们要决定：下一个像素是 (x+1, y) 还是 (x+1, y-1)？

中点的坐标为 (x+1, y - 0.5)。我们将中点代入圆的方程：

  • 如果 d < 0，中点在圆内 → 选择上方像素 (x+1, y)
  • 如果 d ≥ 0，中点在圆外或圆上 → 选择下方像素 (x+1, y-1)

为了避免浮点运算，将 d 乘以 4（实际实现中使用整数化版本）：

直觉解释：初始 d = 1 - r 比较的是从 (0, r) 开始的第一个决策——当 r 很大时，d 为负数，意味着最开始的几步应该保持 y = r（停留在圆的上方）。2*x + 3 中的 3 来自 (x+1)² - x² + 常数调整，5 来自 (x+1)² - x² + (y-0.5)² 在 y 减 1 后的变化。

整个过程没有乘法——只有位移（乘以 2 可以用左移实现）和加减法。这对于 1970 年代的硬件来说是巨大的性能优势。

Region 1（x 占主导，|slope| ≤ 1）：x 每次递增 1，决策是否减小 y。中点取 (x+1, y-0.5)：

继续直到 b²x ≥ a²y 时转入 Region 2。

Region 2（y 占主导，|slope| > 1）：y 每次递减 1，决策是否增加 x。中点取 (x+0.5, y-1)：

为什么需要两区域？因为在椭圆的不同位置，”哪一侧”变化更快是不同的。在扁椭圆（a >> b）的顶端，x 变化快 y 几乎不变；在侧边则反过来。圆的算法之所以只需要一个区域，是因为它的 x 和 y 变化速率总是对称的。

椭圆也利用 4 路对称性：如果 (x, y) 在椭圆上，那么 (±x, ±y) 四个象限的点都在椭圆上。

为什么不用三角函数参数化？

用 x = r*cos(θ), y = r*sin(θ) 遍历角度也能画圆，但存在两个问题：

  1. 浮点三角运算昂贵（尤其是 1970 年代）
  2. 像素间距不均匀——在 θ 接近 45° 时像素密集，接近 0° 或 90° 时稀疏，可能留下空洞

Bresenham 算法恰好解决了这两个问题：纯整数运算 + 确保像素连续无空隙。

设计决策：

  • PPM 格式：选择 PPM (P6 binary) 而非 PNG，因为 PPM 是最简单的无损图像格式，可以用 fprintf/fputc 直接写入而不依赖任何库。验证阶段会将其转为 PNG。
  • 分离验证层：验证逻辑与绘制逻辑完全分离，通过 collectCirclePixels() / collectEllipsePixels() 在独立的临时图像上运行算法，避免污染输出。
  • 对称性测试使用 set 去重：将八分圆映射到第一象限，使用 std::set 确保每个像素只被计数一次，然后验证所有 8 个对称位置都存在。
  • 径向误差公式：对圆使用欧氏距离误差 |√(dx²+dy²) - r|；对椭圆使用隐式方程误差 |x²/a² + y²/b² - 1|。这是两种更适合各自几何特性的度量方式。

关键点解释：

  1. d = 1 - r 而非 1.25 - r：将原始推导的浮点数 1.25 - r 缩放并取整。由于 d 的符号决定了选择，常数项的整数近似不影响决策正确性。

  2. 2*x + 3 的来历：在 f(x+1, y-0.5) 表达式中，(x+1)² - x² = 2x+1，加上从 f(x,y-0.5) → f(x+1,y-0.5) 的增量调整，总和为 2x+3。

  3. 每一项都是整数运算：x、y、d 都是整数，递增项也是整数。没有浮点数、没有除法、没有乘法（2*x 可用位运算 x << 1）。

椭圆算法 Region 1

为什么决策参数中有 rx2 >> 2：

在推导中点决策时，f(x+1, y-0.5) 会产生 (1/4)×a² 项。为避免浮点，用整数右移 rx2 >> 2 近似。这引入了一个微小误差（当 a² 不是 4 的倍数时），但不影响像素选择的正确性——因为决策仅依赖 d 的符号，小的常量偏置不会改变符号（除了极端的边界情况，那些情况下两种选择在视觉上几乎无差异）。

椭圆算法 Region 2

Region 1 和 Region 2 的本质区别：

Region 1 是从顶部开始向下走——x 大步前进，y 小步调整。Region 2 是从最右开始向左走——y 大步前进，x 小步调整。两者的决策逻辑完全对称但交换了 a² 和 b² 的角色。

常见易错点：

  1. Region 1 和 Region 2 的边界条件：ry2 * x < rx2 * y vs rx2 * y <= ry2 * x。注意一个用 < 一个用 <=——这样可以避免在交界处漏画或重复画像素。
  2. Region 2 的决策参数 d2 的递推项中，-2*x + 2 的 +2（而非 +3）是因为在 Region 2 中，中点是 (x+0.5, y-1)，参数化方式不同。

对称性验证

验证逻辑的精妙之处：

  • 使用 std::set 而非 std::vector：确保每个像素只被计数一次（例如 oct0 和 oct1 可能在 45°线上产生相同的像素对）
  • 映射策略：u = |dx|, v = |dy|; if(u < v) swap(u,v) 将任何八分圆的像素统一映射到第一八分圆，再反向验证所有 8 个位置
  • 返回值用比率而非绝对数量：这个值在 0（完全对称）和 1（完全不对称）之间，便于比较不同半径的结果

径向误差验证

为什么用平均径向误差：这是衡量圆”有多圆”最直观的指标。任何像素到圆心的距离与真实半径 r 的偏差告诉我们这个像素偏离理想圆多远。对于 Bresenham 算法，理论最大误差约 0.5 像素（半个像素宽度）。

椭圆的验证则不同——对于椭圆，直接计算”径向距离”没有意义（因为没有单一半径）。我们使用隐式方程误差 |x²/a² + y²/b² - 1|，它衡量绘制的像素点偏离椭圆方程的程度。这种验证方法的物理意义是：对于完美绘制的椭圆，所有像素点都会使该表达式接近 0。

踩坑实录

坑 1：椭圆 Region 2 决策参数初始化

症状：画一个扁椭圆（rx=80, ry=40）时，底部有一个像素偏出了边界。

错误假设：以为 Region 2 的 d2 可以直接复用 Region 1 的逻辑，只是交换 a 和 b 即可。

真实原因：Region 2 从 (rx, 0) 开始而不是从 (0, ry) 开始，起始点的 f 值不同。Region 1 从 (0, ry) 开始，而 Region 2 从 (rx, 0) 开始。两条路径的初始决策参数推导不同。

具体来说，Region 1 在 (0, ry)：f(1, ry-0.5) = b²×(1)² + a²×(ry-0.5)² - a²b²
Region 2 在 (rx, 0)：f(rx-0.5, 1) = b²×(rx-0.5)² + a²×(1)² - a²b²

坑 2：Region 切换边界条件

症状：在 rx=120, ry=90 的椭圆上，45° 线附近出现了重复像素（两个相邻像素都画在同一个 xy 位置）。

错误假设：以为两个区域可以无缝拼接。

真实原因：Region 1 的循环条件是 ry2 * x < rx2 * y（严格小于），而 Region 2 是 rx2 * y <= ry2 * x（小于等于）。如果两者都用 <=，会在边界上重复绘制像素；如果都用 <，会在边界上漏掉像素。只有 < + <= 的组合才能恰好覆盖。

修复方式：仔细设计边界条件，确保每个像素恰好被绘制一次。这是标准教材中也有 warning 的地方。

坑 3：决策参数 d 的范围和溢出

症状：画大椭圆（rx=500, ry=300）时像素偏移，在 4 个象限的某个位置出现裂缝。

错误假设：以为 int 足够存下所有中间结果。

真实原因：椭圆决策参数中涉及 rx2 * ry 这样的计算。当 rx=500 时，rx2 = 250000，乘以 ry=300 得到 75000000，仍在 int 范围内。但当 rx 更大时可能溢出。虽然我们的测试用例都在安全范围内，但生产代码应该注意这一点。

经验教训：任何涉及平方 (rx*rx) 再乘法的表达式都要仔细检查数值范围。对于大型绘制建议使用 long long 或更安全的类型。

总结与延伸

技术要点回顾

Bresenham 圆和椭圆算法是光栅化图形学的基础算法，它将连续几何转换为离散像素，使用纯整数递增决策实现高效绘制：

  1. 圆：8-way 对称 + 单一决策参数增量更新，每次迭代只需 2 次加减法和 1 次比较
  2. 椭圆：4-way 对称 + 两区域策略，在斜率变化的地方切换驱动轴
  3. 验证：对称性、径向误差、像素计数三重量化保证

局限性

  • 大写实心圆：Bresenham 算法只画轮廓。填充实心圆需要额外的扫描线填充（横跨每条扫描线在内部画水平线段）
  • 子像素精度：在低分辨率下，小圆（r < 5）看起来像是多边形而非光滑曲线——这是离散化的固有局限
  • 抗锯齿：纯 Bresenham 算法产生的边缘是”硬”的，没有平滑过渡。要获得更好的视觉效果，需要配合抗锯齿技术（如 Wu 的圆形算法）
  • GPU 不适用：在 GPU 上，直接对每个屏幕像素判断是否在圆内（shader + 距离函数）通常比逐像素步进的 integer 算法更高效——因为 GPU 有大量并行单元。Bresenham 更适合 CPU 串行绘制场景

可以继续探索的方向

  1. Wu 抗锯齿圆形算法：在 Bresenham 基础上，为相邻的两个候选像素各分配一个透明度值，产生平滑边缘
  2. 填充算法：有序边表扫描线填充——将圆的轮廓与水平扫描线求交点，填充线段
  3. 椭圆弧绘制：只画椭圆的一段弧，这在 UI 绘制中非常实用（进度条、仪表盘）
  4. NURBS 曲线光栅化：将本文的思想扩展到更一般的参数曲线
