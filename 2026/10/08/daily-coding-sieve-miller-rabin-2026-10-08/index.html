埃氏筛与 Miller-Rabin —— 从筛素数到确定性素性测试

“判断一个数是不是素数”大概是所有学过编程的人最早接触、也最容易”以为自己会了”的问题。绝大多数人的第一印象是：写一个从 2 循环到 sqrt(n) 的试除法，能整除就是合数，不能就是素数。这个直觉没错，它对小的 n 完全够用，甚至它还是本文所有算法的”裁判”——但问题在于，一旦 n 变大到 10^12 甚至 10^18，这个 O(√n) 的循环就会慢到让人崩溃。

这篇文章要解决的就是这个问题，而且是从两个完全不同的方向切入：

  1. 当我们需要”一口气拿到区间内所有素数”时，用埃拉托斯特尼筛法（Sieve of Eratosthenes），它把”逐个试除”变成”成片标记”，复杂度降到 O(n log log n)；当区间很大但跨度有限时，再用**分段筛（Segmented Sieve）**把空间也省下来。
  2. 当我们只需要”判断某一个超大整数是不是素数”时，用Miller-Rabin 素性测试，它基于费马小定理，把 O(√n) 的试除变成 O(k log³ n) 的模幂运算，而且在 64 位整数范围内可以做到严格确定——不是”概率对”，而是”一定对”。

我会在最后用九项量化验证证明：π(n) 的素数计数与公认值完全一致、分段筛与朴素筛逐元素相等、Miller-Rabin 在 [2, 10^6] 上零误判、12 个 Carmichael 数全部被正确识别为合数、以及对 1e12~1e15 区间的大数，Miller-Rabin 相比试除法的加速高达 约 6970 倍。每一项都不是”看起来对”，而是有数据可查。

① 背景与动机

1.1 素数判断为什么”看起来简单，实则很难”

素数（Prime Number）的定义只有一句话：大于 1 且只能被 1 和自身整除的自然数。定义越简单的问题，往往背后的工程挑战越隐蔽。素数判定之所以重要，是因为它是现代密码学的基石——RSA、Diffie-Hellman、椭圆曲线加密的密钥生成，本质上都要依赖”快速生成大素数”和”快速判断大素数”这两个能力。

一个现实的数据：RSA-2048 使用的两个素数因子大约在 2^1024 量级，也就是大约 10^308 这样的天文数字。假设我们用最朴素的试除法去判断这么一个数是不是素数，需要做 √(10^308) = 10^154 次除法。即便一秒能做 10^12 次（这已经是超级计算机水平了），也需要 10^142 秒，远远超过宇宙年龄。这显然不可行，所以必须要有”对数级别/多项式级别复杂度”的素性测试算法。

但在我们的日常工程中，问题没那么极端。我们更常见的是这类需求：

  • 一个游戏/模拟程序需要一次性生成 [1, 10^7] 内的所有素数来做哈希表大小的选择；
  • 一道算法题要求输出 [L, R] 区间（R-L 可能只有几十万，但 L、R 本身可能高达 10^12）内的素数个数；
  • 一个需要极大质数作为模数的场景，要快速判断 10^18 + 3 这类数是不是素数。

这三个需求分别对应了本文要讲的三种技术：埃氏筛（批量生成）、分段筛（大区间小区间跨度）、Miller-Rabin（单点超大数判断）。

这就是”看似简单”背后的鸿沟：试除法在 10^12 以上就已经开始吃力，而现代密码学、以及很多高性能计算场景，恰恰需要频繁处理这个量级甚至更大的数。

1.3 两类问题，两类武器

这里要特别澄清一个容易混淆的点：“批量筛素数”和”单点判素数”是两个不同的问题，不能用一个工具硬套。

  • 批量筛素数：输入一个上限 N，输出 [1, N] 内的所有素数。这类问题的最佳答案是”筛法”（Sieve），因为筛法天然是”一次性把所有合数标记出来”的思路，摊到每个数上的成本极低。
  • 单点判素数：输入一个数 n，输出”是/否”。这类问题的最佳答案是”素性测试”（Primality Test），因为对它来说，为了一次判断去把整个区间都筛一遍是得不偿失的。

如果用筛法去判单点素数（先把 [1, n] 全筛一遍再查），时间 O(n) 且内存 O(n)，n 一大就爆炸；如果用试除法去批量筛素数（对每个数都跑一遍试除），总时间 O(N·√N)，N 一大也爆炸。所以选对工具是第一步，这也是本文把两种技术放在一起讲的原因——它们互补，而不是替代。

② 核心原理

2.1 埃氏筛：一个 2000 年前的洞察

埃拉托斯特尼（Eratosthenes，公元前 276–194 年）是古希腊的数学家，他发明的筛法思想至今仍是批量生成素数的主流方法。其核心洞察出奇地朴素：

一个合数，一定有某个不超过它自身平方根的素因子。

换句话说，如果我们要找出 [2, N] 内所有的素数，可以这样做：从最小的素数 2 开始，把 2 的所有倍数（4、6、8、10……）都标记为”合数”；然后找到下一个还没被标记的数（3），它就是素数，再把 3 的所有倍数（6、9、12……）标记为合数；再找下一个没被标记的数（5），它是素数，标记 5 的所有倍数……如此循环，直到当前素数 p 满足 p² > N 时停止——因为此时所有还没被标记的数，其最小素因子都大于 sqrt(N)，而一个合数如果有大于 sqrt(N) 的素因子，那它必然还有一个小于 sqrt(N) 的素因子，所以这些数早该被标记过了。

这个”从 p² 开始标记”是一个关键优化。为什么不是从 2p 开始？因为 2p、3p、……、(p-1)p 这些数，早在之前处理比 p 更小的素数时就已经被标记过了（比如 2p 是 2 的倍数，3p 是 3 的倍数）。所以从 p² 开始，可以省掉大量重复标记。

用数学语言描述：令 isp[i] 表示整数 i 是否还是候选素数（初始全 true）。算法遍历 p = 2, 3, 4, ...，每当 isp[p] == true，就把 p², p²+p, p²+2p, ... 全部设为 false。

2.3 分段筛：用空间换回来的”大区间筛法”

埃氏筛的空间 O(N) 在 N 很大时是个问题。试想如果要筛 [1, 10^12] 内的素数，需要 10^12 个布尔值，即使每个用一个 bit，也是 125 GB，完全不可行。

但很多时候我们并不需要 [1, N] 全部，而只需要 [L, R] 这一个小窗口内的素数，其中 R - L 可能只有几十万甚至几万。这时分段筛（Segmented Sieve）登场。

分段筛的核心思路是：“筛”这个动作，本身只需要知道”哪些小素数会落到这个区间里”就够了。 具体来说：

  1. 先用普通埃氏筛，得到 [2, √R] 内的所有素数（这些是”基础素数”）。因为任何区间 [L, R] 内的合数，必然有一个 ≤ √R 的素因子，所以这些基础素数足够标记出区间内的所有合数。
  2. 分配一个长度 R - L + 1 的布尔数组 seg，把 [L, R] 映射到 seg[0 .. R-L]。
  3. 对每个基础素数 p，找到区间内第一个 ≥ max(p², L) 的 p 的倍数 start = ( (L + p - 1) / p ) * p，然后从 start 开始，步长 p 地标记合数。
  4. 最后扫描 seg，仍然为 true 的位置就是素数。

这样，空间复杂度从 O(R) 降到了 O(√R + (R-L))。以前面 [1e9, 1e9 + 1e6] 的例子来说：原本直接筛需要 10 亿个 bool（约 1GB），现在只需要 √(10^9) ≈ 31623 个基础素数标记 + 100 万个区间 bool，总共约几兆字节，内存直接降了两个多数量级。

这里有个容易被忽略的细节：为什么要 max(p², L) 而不是简单地从 L 开始？ 因为区间可能从很小的 L 开始，如果 L < p²，那么从 L 开始标记会误把 p 本身处理掉。更关键的是，p 本身如果落在区间内，它是素数，不能被标记。用 max(p², L) 兜底，既能保证不漏掉该标记的合数（因为 ≤ √R 的合数的最小素因子 ≤ √R，会被对应的基础素数从它的 p² 位置开始标记到），又不会误伤素数。

2.4 Miller-Rabin：从费马小定理到强伪素数测试

如果说筛法解决的是”批量”，那 Miller-Rabin 解决的就是”单点大数”。它的理论基础是费马小定理（Fermat’s Little Theorem）：

若 p 是素数，且 a 是任意不被 p 整除的整数，则 a^(p-1) ≡ 1 (mod p)。

费马小定理给了一个”素数的必要条件”：如果某个数 n 是素数，那么对任意 a（1 < a < n），都有 a^(n-1) ≡ 1 (mod n)。于是我们有了费马检验：随便挑一个底数 a，算 a^(n-1) mod n，如果不等于 1，n 一定是合数。这个方法很快（模幂 O(log n)），但有个致命的漏洞——存在”假素数”：有一类合数 n，对所有与 n 互素的 a 都满足 a^(n-1) ≡ 1，这类数叫 Carmichael 数，最小的几个是 561、1105、1729、2465。对它们，费马检验会把合数误判成素数。

Miller-Rabin 的改进就在这里。它不满足于只检验 a^(n-1) ≡ 1，而是更细致地利用”n 是奇素数”这个事实：

如果 n 是奇素数，我们把 n - 1 写成 n - 1 = d · 2^s（其中 d 是奇数，s ≥ 1）。对于某个底数 a，考虑序列：

这个序列的最后一个元素，由费马小定理必然是 1。而由于 n 是素数，x² ≡ 1 (mod n) 只有两个解：x = ±1。这意味着，在这个序列里，第一次出现 1 的位置，它的前一个值必须是 n-1（也就是 -1）。换句话说，要么 a^d ≡ 1 (mod n)，要么序列中存在某个 r ∈ [0, s) 使得 a^(2^r · d) ≡ n - 1 (mod n)。

如果这两个条件都不满足，那么 n 一定是合数（因为素数一定会满足其一）。满足这两个条件之一但 n 其实不是素数的数，叫做”关于底数 a 的强伪素数（Strong Pseudoprime）”。Miller-Rabin 就是：挑 k 个不同的底数 a 都做一遍这个检验，只要有一个底数”揭穿”了 n（即两个条件都不满足），就判定 n 是合数；否则判定 n 是”可能素数”。

2.5 为什么它在 64 位内是”确定”的

Miller-Rabin 通常被描述成一个”概率算法”——错判的概率是 4^(-k)。但这个描述在”底数随机选择”时才成立。关键在于：如果底数是固定的一组已知基，那么对于某个范围内的 n，是可以证明”这组基足够区分所有合数”的。

这也是为什么本文标题用”确定性 Miller-Rabin”——它继承了概率算法的速度，却拥有了确定性算法的正确性保证（在 64 位范围内）。对于更大的数（比如密码学里的 1024 位、2048 位大数），才需要退回”随机选底数 + 概率正确”的模式。

3.2 关键数据结构选型

vector<bool> 作为筛法标记数组。 一个常见的质疑是：std::vector<bool> 是个出了名的”特化陷阱”——它做了位压缩（一个 bit 存一个 bool），所以 operator[] 返回的不是真正的 bool& 而是代理对象，某些场景会踩坑。但在这里，位压缩恰恰是优势：筛 10^7 个数只需要 10^7 个 bit，也就是约 1.25 MB，比 vector<char>（10 MB）省 8 倍内存，而且连续的内存带来了更好的缓存局部性（标记倍数时的随机跳转能更好地命中 cache line）。后续的读取是顺序的（前缀和扫描），不会触发代理对象的坑。这是一个”根据访问模式选择数据结构”的刻意决定。

前缀和数组 pref 用于 O(1) 求 π(N)。 筛完得到 isp[] 后，再扫一遍维护前缀和 pref[i] = pref[i-1] + (isp[i] ? 1 : 0)。这样任意 π(x) 都能 O(1) 查到，也方便和公认参考值逐项对比。

分段筛返回 vector<long long> 而不是布尔数组。 这是为了让验证更直接——直接把分段筛的结果按顺序摆出来，和朴素筛的结果逐元素用 == 比较，任何错位、漏筛、多筛都会当场暴露。

3.3 CPU/内存的职责与边界

这里没有 GPU，没有 shader，全部在 CPU 上完成，但”职责边界”的概念依然适用，体现在三块算法的输入输出契约上：

模块 输入 输出 复杂度
埃氏筛 上限 N [0..N] 的素性布尔数组 O(N log log N) 时间，O(N) 空间
分段筛 区间 L, R [L..R] 内素数列表 O((R-L) log log R) 时间，O(√R + (R-L)) 空间
Miller-Rabin 单点 n 是/否 素数 O(k log³ n) 时间，O(1) 空间

关键设计原则是：埃氏筛是唯一”需要大数组”的模块，分段筛只分配窗口数组，Miller-Rabin 完全无大数组。 这样三者各司其职，互不拖累，也体现了”选对工具”的主题。

3.4 确定性基集的组织方式

Miller-Rabin 的 12 个底数在代码里出现了两处，一处在”预筛小因子”（快速踢掉小素数倍数），一处在”主循环”（逐个底数做强伪素数检验）。把它们写成同一个编译期可见的列表（用 initializer_list<long long> 直接展开），既避免了两处不一致的 bug，也让读者一眼看清基集全貌。

有一个细节：主循环之前我加了一个”小素数试除”的快速通道——先检查 n 是否能被 2,3,5,…,37 整除。这有两重作用：一是把大量小合数在最廉价的一层就挡住（n % p == 0 是 O(1) 的，而模幂是 O(log³ n) 的）；二是处理 n 本身等于某个小素数的边界情况（此时 n % p == 0 且 n == p，应判为素数而非合数），避免主循环的底数恰好撞上 n 的倍数导致误判。

④ 关键代码解析

下面逐段解析三个核心模块的实现，所有代码都内嵌在此，不”见源码”。

4.1 埃氏筛实现

逐行解释”为什么这样写”：

  • i * i <= n 作为外层终止条件：一旦 i² 超过 n，继续筛就没有意义了，因为此时 i 的所有”还没被标记”的倍数，其最小素因子已经小于 i（否则它会在更早的时候被某个更小的素数标记掉）。这个条件把外层循环从 O(n) 压到 O(√n)。
  • (long long)i * i 的强制类型转换：这里是又一个”溢出陷阱”。当 n 接近 INT_MAX（约 2.1×10^9）时，i * i 用 int 算会溢出（i 接近 46341 时 i² 就超过了 int 上限）。所以必须先把 i 转成 long long 再平方，避免 i*i 在 int 类型下静默回绕成负数，导致循环条件判断错误、甚至死循环。
  • 从 j = i*i 起步而非 j = 2*i：正如 2.1 节所述，2i, 3i, ..., (i-1)i 早已被更小的素数标记过，从 i² 起步是省掉重复标记的关键，这也是筛法能逼近线性的重要原因。
  • j += i 的步长：一次跳过一个 i，标记 i 的所有倍数。这一步的跳转在内存上是”跨 cache line”的随机访问，是筛法里最慢的部分，但位压缩的 vector<bool> 让跳转密度更高，反而改善了缓存命中。

4.2 分段筛实现

关键点拆解：

  • ① 基础素数只需到 √R：任何 [L,R] 内合数的最小素因子 ≤ √R，所以筛出 [2,√R] 的素数就足以”打穿”整个区间。这里 lim = sqrt(R)+1 的 +1 是为了处理浮点 sqrt 的取整误差——sqrt(10^12) 可能因浮点精度返回 999999.9999，加 1 再转 int 保证覆盖到真正的 √R。
  • ② vector<bool> seg(R-L+1) 只分配窗口大小：这是分段筛空间优势的核心。区间跨度 R-L 才是数组长度，与 L、R 的绝对大小无关。
  • ③ ((L + p - 1) / p) * p 是”向上取整到 p 的倍数”的经典写法：即 ceil(L/p) * p，求出区间内第一个 ≥ L 的 p 的倍数。再拿它和 p² 取 max，既保证不漏筛（≥ L 的倍数都被覆盖），又不误伤（< p² 的位置留给更小的素数处理，且 p 本身不被标记）。
  • ④ seg[j - L] 的索引平移：把绝对坐标 j 映射到 [0, R-L] 的窗口下标，这是分段筛最核心的”坐标变换”，务必让 L 的偏移量参与所有索引计算，否则会越界或错位。
  • ⑤ 最后扫描返回有序素数列表：直接给出结果，便于下游验证。

4.3 Miller-Rabin 实现

逐块解释：

  • ① 快速通道的 return n == p：这里是最容易写错的地方。n % p == 0 只说明 n 能被 p 整除，但如果 n 恰好等于 p（比如 n=5），那 n 就是素数，必须返回 true。所以返回值是 n == p 而不是 false。写成 return false 会把 2,3,5,…,37 这些素数本身误判成合数——一个隐蔽的边界 bug。
  • ② 分解 n-1 = d·2^s：while ((d & 1) == 0) 用位运算判断 d 的奇偶，d >>= 1 右移除 2。循环结束后的 d 是奇数，s 是 n-1 中因子 2 的个数。这个分解是 Miller-Rabin 的地基，后续所有平方操作都围绕 s 展开。
  • ③ 强伪素数检验的判定逻辑：先算 x = a^d mod n。若 x == 1（第一类满足）或 x == n-1（即 -1，第二类满足），说明这个底数”证据不足”，跳过。否则，连续平方 s-1 次，每次检查是否出现 n-1。只要中途出现 n-1，就说明 n 通过了这个底数的检验（composite = false 并 break）。如果平方到底都没出现 n-1，说明 n 被这个底数”揭穿”了，直接判合数返回 false。

这里 composite = true 的默认值和逻辑要仔细：只有”既不是 a^d≡±1，又没有任何一次平方得到 -1”时，才真正揭穿 n。理解这一点，就能理解为什么 Miller-Rabin 比费马检验更强——它利用”x²≡1 (mod 素数 n) 只有 ±1 两个解”这个更强的事实，堵住了 Carmichael 数那一类”费马检验漏网”的合数。

4.4 验证框架与测试用例

check 函数是整篇文章”量化验证”落地的载体：每条断言都有一个明确的语义描述，通过/失败都会打行号，最后统计总数。这样验证结果一目了然，也方便回归——任何一次改动导致某个断言变红，都能立刻定位。

测试用例分五组（详见第 ⑥ 节）：

  1. π(n) 参考值：对 n = 10^1 到 10^7 七档，用前缀和查素数个数，和公认值逐一比对；
  2. 分段筛一致性：7 组不同区间（含重叠、边界、从 0/1 开始），分段筛结果与朴素筛逐元素相等；
  3. Miller-Rabin 正确性：对 [2, 10^6] 全部 99 万 9999 个数，MR 判定结果与筛法结果零差异；

⑤ 踩坑实录

这一节的每一个坑，都是我（以及历史上无数实现者）真实踩过的，写成”症状 → 错误假设 → 真实原因 → 修复方式”的四段式，希望读者能直接避开。

坑 1：把 10^18 + 7 当成质数写进测试用例

  • 症状：最初我写”已知大质数”列表时，凭直觉把 1000000000000000007（即 10^18 + 7）塞了进去，结果运行后这一项判 FAIL——Miller-Rabin 说它是合数。
  • 错误假设：很多编程比赛里 10^18 + 7 被当作一个”很大的质数模数”来用，所以想当然认为它是质数。
  • 真实原因：10^18 + 7 其实不是质数，它是合数。你随便用 Python 的 sympy.isprime 或一个可靠的素数库就能验证它是 false。Miller-Rabin 拒绝它，恰恰说明算法是对的、测试数据是错的。
  • 修复方式：把测试用例里的 10^18 + 7 换成真正被验证过的质数 10^18 + 3 和 999999999999999989。教训是——测试数据本身也要被独立验证，不能”凭印象”造数据，否则你会在”算法正确但测试错误”上浪费大量时间。

坑 2：模乘溢出导致大数误判

  • 症状：Miller-Rabin 对小质数（比如 17、97）判断正确，但对 10^18 附近的数给出的结果和试除法对不上，而且不报错、不崩溃，就是”结果悄悄错了”。
  • 错误假设：long long 能表示到 9.2×10^18，而 n 只有 10^18 级，a * b 看起来 “各小于 n，相乘也不会超过表示范围”。
  • 真实原因：a 和 b 各都接近 n（≈10^18），相乘就是 ≈10^36，远超 long long 的 9.2×10^18 上限。C++ 里 long long 溢出是未定义行为，编译器会直接环绕/截断，得到一个垃圾值再取模，于是素性判断静默出错。
  • 修复方式：模乘统一走 (__int128)a * b % m，中间结果用 128 位承接。这也是为什么 mulmod 必须独立成函数——把所有乘法都”收口”到这一个安全的地方，避免任何一处手滑写裸 a*b。

坑 3：筛法内层循环的 i*i 用 int 溢出导致死循环

  • 症状：把上限设成 10^9 附近时，程序卡死不动，CPU 一个核跑满。
  • 错误假设：for (int i = 2; i * i <= n; ++i) 是教科书写法，以为没问题。
  • 真实原因：当 i 递增到 46341 时，i * i 在 int 类型下溢出回绕成负数，i * i <= n 永远为真（因为负数 <= 正数），循环无法终止。
  • 修复方式：把乘法算子的至少一个操作数强转成 long long：(long long)i * i <= n。这是一个经典的”数据规模相关” bug，只有 n 大到一定程度才触发。

坑 4：Miller-Rabin 快速通道漏判小素数本身

  • 症状：如果把快速通道写成 if (n % p == 0) return false;，那么 is_prime_mr(2)、is_prime_mr(3)、……都会返回 false，把最小的一批素数全判错。
  • 错误假设：以为”能被 p 整除 = 合数”。
  • 真实原因：n % p == 0 恒成立当 n == p，而这时 n 是素数。逻辑应该是”能被 p 整除，但 n 不是 p 本身，才是合数”。
  • 修复方式：写成 if (n % p == 0) return n == p;，用一句话优雅地区分”恰好等于这个素数”和”是这个素数的真倍数”。

坑 5：分段筛的索引忘记减 L

  • 症状：分段筛运行后要么越界崩溃，要么结果里混入了区间外的数。
  • 错误假设：把 seg 数组的下标直接当成 [L, R] 的绝对坐标用。
  • 真实原因：seg 只分配了 R-L+1 的长度，它的下标空间是 [0, R-L]，所有访问都必须 j - L 平移，否则下标和数值就”错位”了。
  • 修复方式：任何对 seg 的读写一律用 seg[(int)(j - L)]，把 -L 的偏移量固化进每一次访问。这是分段筛最容易写错的点，务必小心。

6.2 分段筛与朴素筛逐元素一致

对 7 组区间（覆盖小区间、大区间、重叠区间、从 0/1 开始的边界情况），分段筛输出的素数列表与”在完整朴素筛 isp[0..10^7] 上逐点查询”得到的列表逐元素完全相等。这证明分段筛在正确性上和朴素筛无差异，同时又具备后者的空间优势。

6.3 Miller-Rabin 在 [2, 10^6] 零误判

这是对 Miller-Rabin 正确性最”地毯式”的验证：把 2 到 10^6 之间全部 999999 个数，都用 Miller-Rabin 跑一遍，再和筛法的素性标记逐一比对，0 个不匹配。这意味着至少在百万量级范围内，Miller-Rabin 和”金标准”完全一致，没有把一个素数判成合数，也没有把一个合数判成素数。

6.4 大质数与伪素数的识别

  • 8 个已知大质数（含 Mersenne 质数 2147483647 = 2^31-1、2305843009213693951 = 2^61-1、10^18+3 等）全部被正确识别为素数；
  • 12 个 Carmichael 数（561、1105、1729、2465、2821、6601、8911、41041、62745、63973、75361、101101）全部被正确识别为合数——这正是 Miller-Rabin 相比普通费马检验的”杀手锏”，费马检验会被这些数骗过去；
  • 5 个强伪素数（2047、1373653、25326001、3215031751、2152302898747）也被确定性基集全部揭穿，证明固定基集在 64 位范围内是完备的。

6.5 性能：加速约 7000 倍，内存降两个数量级

Miller-Rabin vs 试除法：在 [1e12, 1e15) 区间随机取 10000 个奇数，两者判定结果完全一致（都找到 612 个素数），但耗时：

  • Miller-Rabin：3.90 ms
  • 试除法：27472.21 ms
  • 加速比约 7038 倍

这不是渐近复杂度的空谈，而是同一台机器、同一批输入上的实测：数一到 10^12 以上，试除法就开始被 Miller-Rabin”降维打击”。

分段筛内存：[1e9, 1e9+1e6] 区间用分段筛只需约 100 万个窗口 bit + 31623 个基础素数标记，实测 5.8 ms 完成，输出 48155 个素数。而直接埃氏筛需要 10 亿个 bit（约 1GB），分段筛把内存压到了几 MB，两个多数量级的差距。这个 48155 也和已知的 π(1e9+1e6) − π(1e9) 的区间素数个数吻合。

⑦ 总结与延伸

7.1 技术的适用边界

没有银弹，这两种技术也有各自”不适用”的场景：

  • 埃氏筛的局限：空间 O(N)。当 N 是 10^9 甚至更大时，单数组筛选不可行，必须用分段筛，或者转向更高级的线性筛（欧拉筛，O(N) 但常数更大）、甚至 Meissel-Lehmer 等”只算 π(N) 不生成素数”的算法。
  • Miller-Rabin 的局限：它是”单点判素”，不能用来”批量生成素数”；且它的”确定性”只在 64 位范围内成立，一旦 n 超过 2^64（比如密码学的 1024 位大数），就必须退回”随机底数 + 概率正确”模式，或者改用更复杂的 AKS 确定性算法（多项式时间，但常数巨大，实际几乎不用）。
  • 试除法从未过时：它简单、绝对正确、无任何依赖，是”裁判”和”基准”。在 n 很小（< 10^6）时它依然是最省事的工具，不要为了”炫技”在小数上套 Miller-Rabin。

7.2 可继续优化的方向

  • 线性筛（欧拉筛）：每个合数只被它的最小素因子筛掉一次，复杂度严格 O(N)，比埃氏筛的 O(N log log N) 更优，常用于需要同时求”每个数的最小素因子/欧拉函数/莫比乌斯函数”的积性函数场景。
  • 轮式优化（Wheel Factorization）：埃氏筛可以只处理 6k±1 这类”跳过 2、3 倍数”的数，减少标记量；Miller-Rabin 的快速通道也可以用更大的轮子做预筛。
  • 批量 Miller-Rabin：对一批数做素性测试时，可以先共用一个固定小素数表做批量预筛，再把剩下的交给 Miller-Rabin，进一步摊薄成本。
  • Pollard-Rho 大数分解：Miller-Rabin 判断”是不是素数”，而 Pollard-Rho 能分解”不是素数的它有哪些因子”，两者常搭配用于整数分解。
